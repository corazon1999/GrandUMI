# GrandUMI 卡牌效果实现架构与流程

> 总览文档：理解一张卡的效果如何从「卡面文字」落到「运行时执行」。
> 配套细则见同目录 `_cs_spec.md`（脚本）、`_dsl_spec.md`（DSL）。

## 一、总览：两套实现 + 统一分发

每张卡的效果有两种实现方式，由 `EffectRuntime.Resolve` 按卡号**二选一分发**：

```
玩家动作/游戏事件
      ↓
EffectRuntime.Resolve(state, ownerIdx, source, trigger, prompts, payload)
      ↓
  ① 检查是否被无效化（IsContinuouslyNullified / IsTriggerNullified）→ 是则不发动
  ② ScriptedEffectRegistry.TryGet(卡号) 命中脚本 且 脚本.HandlesTrigger(trigger) → 跑 C# 脚本
  ③ 否则 → DslInterpreter.TryResolve(ctx) 解释 DSL JSON
  ④ finally：最外层(_depth==0)排空 watcher 队列 + 被效果登场卡的【登场时】（DrainWatchers）
```

**关键**：分发是 **trigger 粒度**的——脚本若 `HandlesTrigger` 只返回部分时机，其余时机仍退回 DSL。
所以一张卡可「DSL + 脚本」混用（如 OP16-036：登场时走 DSL，攻击时走脚本）。

上下文沿 `AsyncLocal` 传播（`_ambient`=当前 GameState、`_currentSource`、`_actingSide`、`_depth`、`_draining`），
支持嵌套效果与并发房间隔离。

## 三、核心数据模型

- **`CardInfo`**（静态、只读，来自卡数据）：`Number / Name / Power / Cost / Counter / EffectTags[] / Abilities[] / Trigger / KeyWords...`。`HasKeyword(kw)` 判特征/关键词。
- **`CardInstance`**（运行时状态）：`IsTapped`（横置）、`AttachedDon`、`GainedKeywords`、`Restrictions`（含 `CannotBeRested` 等）、`OncePerTurnUsedKeys`、`CannotActivateNextReset`、`OriginalPowerOverride`、`PowerModThisTurn/Battle/Persistent`、`CostModThisTurn/Persistent`…
- **`EffectContext`**（一次结算的上下文）：`State / OwnerIndex / Source / Trigger / Prompts / Engine / Vars`（`$tgt` 等 DSL 变量存在 `Vars`）。
- **`GameState` / `PlayerState`**：`Players[2]`、`CurrentTurnPlayer`、`ContinuousEffects`、`PendingWatchers`、`PendingEnterFields`；`PlayerState.TurnOnceUsed`（本回合一次性 key 集合）。

## 四、触发时机全表（`EffectTrigger`）

**主动/卡面关键词类**
`OnEnterField`(登场时) · `OnAttackDeclare`(攻击时) · `OnOppAttackDeclare`(对方攻击时) · `OnBlockDeclare`(阻挡时) · `OnKO`(KO时) · `PreKO`(KO前置换) · `OnDamageToLeader`(对领袖造成伤害) · `OnLifeRevealTrigger`(生命触发) · `ActivatedMain`(启动主要) · `EventMain`(事件主要) · `EventCounter`(事件反击)

**回合/时点类**
`OnGameStart` · `OnTurnStart` · `OnMyTurnEnd` · `OnOppTurnEnd` · `OnDonAttached` · `OnDrawCard` · `OnPlayCard` · `OnEnterTrash`

**Wave2 反应式 watcher（队列派发，payload 带相关卡 id）**
`OnCharRested` · `OnCharLeaveField` · `OnLifeLeaveField` · `OnAllyCharEnter` · `OnOppEventPlayed` · `OnOppBlocker` · `OnAllyWillBeKOd`(代替被KO置换) · `OnAllyWillLeaveField`(代替离场置换) · `OnAnyCharKOd` · `OnBattleEnd` · `OnTriggerActivated`(元触发) · `OnHandDiscarded` · `OnDonReturnedToDeck`

**派发依据**：`HasEffectForTrigger(card, t)` = `card.Info.EffectTags` 是否含 `t.ToString()`
（`OnLifeRevealTrigger` 例外，据 `Info.Trigger` 非空）。
> ⚠️ 新卡要被某时机派发，卡数据 `effectTags` 必须含该时机名；否则脚本/DSL 写了也不会触发，派发后空过。

## 六、DSL 写法（`Definitions\*.json`）

一张卡一个条目，按**触发节**组织。`_name`/`_matcher`/`_doc` 是给人看的注释字段。

```jsonc
"OP16-049": {
  "_name": "波特夹斯·D·艾斯",
  "activated": {                          // 节：activated=启动主要
    "cost": { "restSelf": true },         // 成本（冒号前），先付
    "then": [ { "op": "Draw", "n": 1 } ]  // 收益（冒号后），按序执行
  }
}
```

**触发节**：
- `triggers: [ { on, cost?, if?, oncePerTurn?, then[] } ]` — 登场时/KO时/攻击时等
- `activated: { cost?, if?, oncePerTurn?, then[] }` — 启动主要
- `main: { cost?, if?, then[] }` — 事件主要
- `counter` — 事件反击（数组直接执行，或对象带 cost/if）
- `trigger` — 生命牌触发

**执行顺序（DslInterpreter）**：`CheckCondition(if)` → `CheckOncePerTurn` → `PayActivationCost(cost)` → `RunSteps(then)` →（成功后）`MarkOncePerTurnUsed`。**成本天然先于 then。**

**成本原语**（`cost` 对象内，`PayActivationCost`）：`restSelf`(横置自身)、`selfToTrash`(自送废弃)、`donReturn:N`(咚-N放回)、`restActiveDon:N`(横置N活跃咚)、`handDiscard`(弃手牌，数字=强制/对象=可放弃带过滤)、`revealHand`(公开手牌)、`trashOwnCharacter`、`returnOwnStage`、`lifeFaceUp/Down`… （完整见记忆 `dsl-cost-primitives`）。触发段加 cost 会自动弹确认 + 可放弃。

**效果 op（`then[]`，主要类）**：`Choose`(选目标→存 `$var`)、`Draw`、`MillTop`、`KO`、`Rest`、`Activate`、`BounceToHand`、`AddPowerThisTurn/Battle/Persistent`、`AddPowerAll`、`SetPower`、`AddCostMod`、`GiveKeyword`、`AddRestriction`、`PreventActivateNextReset`、`AttachDon`、`PlayFromHandFree`、`PlayCharFromHand/Trash`、`PlayFromTrash`、`SearchDeck`、`LookTopReveal`、`RevealTopThen`、`LookOpponentHand`、`OpponentDiscard`、`ReturnToDeckBottom`、`Nullify`、`MoveCharToLife`、`LifeToHand`、`OppLifeToHand` …
（`Choose` 的 `filter` 支持 `originalPowerLte/Gte`、`originalCostLte`、`keywordContains`、`nameEquals` 等）

> ⚠️ 解释器**静默忽略未知键**，改 DSL 后务必用对应卡集的校验脚本（如 `_eb_validate.js`）确认无拼写错误。

## 七、C# 脚本写法（`Scripted\*.cs`）

DSL 表达不了的（带激活成本的 triggers、对方选牌、复杂条件/多段联动）走脚本：

```csharp
public class OP16_036_Bentham : IScriptedEffect
{
    public string CardNumber => "OP16-036";
    public bool HandlesTrigger(EffectTrigger t) => t == EffectTrigger.OnAttackDeclare;
    public Task Resolve(EffectContext ctx) { /* 用 AtomicOps + ctx.Prompts */ }
}
```

- **注册**：服务器启动时 `ScriptedEffectRegistry.ScanAll` 反射扫描所有 `IScriptedEffect` 实现并按 `CardNumber` 入字典（无需手动注册）。
- **常用工具**：`AtomicOps`（`Draw / RestCard / KO / KOByEffectAsync / BounceToHand / AddRestriction / AttachDonFromCost / PromptRestOwnCards / PromptReturnDonToDeck` …）+ `ctx.Prompts`（`ChooseCards / ConfirmOptional`）。
- **每回合一次**：用 `me.TurnOnceUsed`，启动效果 key 约定 `"{番号}-act:{id}"`；DSL 启动 key 为 `"{id}-Activated"`。

## 八、持续效果（`ContinuousEffect`）

非"一次结算"的常驻效果（光环/静态减费/禁攻/防KO），通常在 `OnEnterField` 注册到 `state.ContinuousEffects`：
- 字段：`PowerDelta / CostDelta / GrantRestriction / GrantKeyword / KoGuard / PreventReset`
- **`Predicate(s, side, card)` 决定作用对象** —— ⚠️ `Scope` 只供前端显示，**作用对象必须写进 Predicate**（如 `card.Id == selfId`），否则全场误生效。
- 费用判定统一走 `GameState.CurrentCostOf`（含 CostDelta 光环）。

---

## 九、Prompt 交互链路

```
脚本/DSL 调 ctx.Prompts.ChooseCards(...) / ConfirmOptional(...)
   → PromptSystem 下发 prompt 快照（kind / text / validChoices / extra）
   → 客户端 PromptOverlay 渲染（卡图反查 findCardById：choiceCards→领袖→舞台→fieldCards）
   → 玩家选择 → GameRequest.respondPrompt → 续接 await 返回所选 id
```
非公开区（卡组/对手手牌）的候选用 `extra.choiceCards` 携带 `{id, number}` 下发卡面。
检索/确认类约定：`choiceCards`=确认到的全部牌，`validChoices`=可点选子集（其余置灰仅供确认）。

## 十、状态下发与回合清理

- **快照**：`StateSnapshotBuilder`（对战公开，已脱敏）按视角下发 `fieldCards`（含 `isTapped / cannotBeRested / cannotActivateNextReset / activatedUsedThisTurn` 等）+ 领袖/舞台扁平字段；`PrivateStateSnapshotBuilder` 供日志/AI训练。
- **回合清理**（`TurnEngine`）：重置阶段尊重 `CannotActivateNextReset`（仅角色，领袖/舞台无条件活跃）；回合末清 `TurnOnceUsed`、`OriginalPowerOverride`、`PowerModThisTurn` 等本回合状态。

## 十一、新增/修改一张卡的 Checklist

1. 查卡面原文 → `卡牌数据_含原文\*.json`，识别**冒号「：」前=成本、按卡面从前到后顺序**（见记忆 `cost-before-colon-execution-order`）。
2. 确认卡数据 `effectTags` 含所需触发时机（缺则补；脚本生成后跑 `_add_tags_from_scripts.js`）。
3. 简单→写 DSL（`Definitions`）；复杂→写脚本（`Scripted`）。
4. DSL 改完跑校验脚本；脚本改完 `dotnet build`（在 `服务端WebSocket` 目录内）。
5. 修卡后写 `修复记录\`，并排查语义相似卡一起改。
6. 「一键更新」上线 → 验证首页 200 + 单人测试。

## 十二、端到端示例（OP16-043【KO时】带成本）

```
撒谎布被KO → BattleEngine 派发 OnKO
  → EffectRuntime.Resolve(OnKO) → 命中脚本 OP16_043_Usopp
    → 检查收益候选(对方费用≤5角色)
    → ChooseCards 选成本(我方《德莱斯罗兹》活跃领袖/舞台) → PromptOverlay 弹窗
    → RestCard(成本横置)
    → ChooseCards 选回手目标 → BounceToHand(对方角色回其持有者手牌)
  → finally 排空 watcher（如离场连锁）
  → 新快照下发双方 → 前端刷新牌桌
```
