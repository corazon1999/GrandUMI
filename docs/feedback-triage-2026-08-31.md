## 状态治理建议

1. QQ 反馈与游戏内反馈统一增加 `triaged / needs_info / fixed / not_bug / duplicate` 状态，并保存 `duplicate_of`、修复提交和最后复测版本。
2. 游戏内反馈写入稳定的脱敏反馈 ID、客户端版本、服务端提交、房间日志关联键和动作 requestId；不要依赖文件名和玩家自由文本关联现场。
3. 修复后由测试服回执或玩家复测更新状态；“代码里看起来已实现”只能标为“待复测”，不能直接标为已修复。
4. 对 P0 对局卡死/跳回合类反馈自动附带权威回合序号、计时截止、连接代次、最近接受动作和终局原因，避免事后只剩 UI 描述。
