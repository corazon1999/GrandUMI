## 二、回合流程（需重点学习）

### 2.1 游戏开始

```
1. 双方进入房间 → 准备（SetPrepare）
2. 双方准备完成 → 显示"游戏开始"
3. 服务器洗牌（MsgShuffle）→ 双方卡组同步
4. 先攻决定（SelectFirst）→ 选择先攻/后攻
5. 初始抽卡 5 张（SelfInit）
6. 从卡组抽与领航卡费用等量的生命牌（InitLife）
   例如：领航卡 Cost=5 → 生命牌 = 5 张
```

### 2.2 回合结构

```
回合开始（TurnStart 事件）
  ├── 回合开始效果检查（领航卡 TurnStart 效果）
  ├── 抽卡阶段：抽 1 张牌（DrawFromDeck）
  ├── 费用恢复（GainDon）：第一回合 +1，其他回合 +2
  │     上限 10（特殊领航卡 OP15-058 上限 6）
  ├── 激活全部费用（ActiveAllDon）
  │
  ├── ★ 主阶段（Main Phase）—— 玩家可自由操作：
  │   ├── 出牌（PlayCard / AppearFromHand）：消耗费用
  │   ├── 使用效果（UseEffect）
  │   ├── 攻击宣言（AttackPhase）→ 进入战斗序列
  │   └── 结束回合（TurnEnd）
  │
  ├── 额外回合（ExtraTurn，可选，由效果触发）
  │
  └── 回合结束（TurnEnd 事件）
      └── 切换到对方回合（SwitchTurn）
```

### 2.3 关键源码位置

| 概念 | 源码 |
|------|------|
| 回合切换 | `GameManager.SwitchTurn()` |
| 回合开始事件 | `EventCenter.Broadcast(MyEventType.TurnStart, ...)` |
| 回合结束事件 | `EventCenter.Broadcast(MyEventType.TurnEnd, ...)` |
| 先攻选择 | `GameManager.SetFirst(bool isFirst)` |
| 额外回合 | `GameManager.ExtraTurn()` |
| 初始抽卡 | `MyDeck.SelfInit()` |
| 初始生命 | `RequestManager.InitLife(camp, lifeNum)` |

### 2.4 学习要点

1. `TurnCount` 从 1 开始，每次 SwitchTurn 或 ExtraTurn 自增
2. `HaveExtraturn` 标志：当某个效果赋予额外回合时设为 true，TurnEnd 时检查
3. `CurrentTurn` 类型为 `CardCamp`（我方/敌方），BattlePhase 只在 None 时才能结束回合
4. 第一回合先攻方费用只 +1（限制先攻优势）

## 三、费用系统（需重点学习）

### 3.1 费用类型（Cost.cs）

```
Total（总费用）  = Active（可用） + Rest（已用）
                    ↑                ↑
                 可花费的费用      本回合已消耗的费用
```

- **上限**：默认 10，特殊领航卡 `OP15-058` 上限为 6
- **锁费用**（`lockCost`）：被效果锁定的费用，无法激活

### 3.2 费用操作列表

| 操作 | 含义 | 源码方法 |
|------|------|---------|
| GainDon | 增加费用 | `Cost.GainDon(int num, bool is_active)` |
| SpendDon | 消费费用 | `Cost.SpendDon(int num)` |
| AttachDon | 给角色卡附加咚（从费用区移动） | `Cost.AttachDon(int num, bool is_active)` |
| ReduceDon | 减少总费用 | `Cost.ReduceDon(int count)` |
| ActiveAllDon | 激活全部（回合开始时调用） | `Cost.ActiveAllDon()` |
| CharaDonReturn | 角色上的咚退回费用区 | `Cost.CharaDonReturn(int num)` |
| LockCost | 锁定费用（某些效果） | `Cost.LockCost(int num)` |

### 3.3 费用检查

```csharp
// 消费前检查
if (Active < cost) return; // 费用不够
// 只有己方回合 & 非战斗阶段才能操作费用
if (CurrentTurn != CardCamp.我方) return;
if (BattleManager.Instance.currenPhase != BattlePhase.None) return;
```

### 3.4 学习要点

1. "咚"（Don）既是费用也是攻击的威力增幅来源
2. 每回合开始自动 GainDon：第一回合 +1，其他回合 +2
3. 出牌时消耗 Active，回合结束时 Rest 在回合计费中被清零更新
4. 给场上角色"附加咚"会消耗费用，角色KO后退还费用到 Rest
5. 只有 `Mouse.State == None / ShowingButton_Hand / ShowingButton_Field` 时才能操作费用

## 四、战斗结算流程（需重点学习）

### 4.1 战斗阶段枚举（BattlePhase）

```
None              → 无战斗（主阶段）
AttackPhase       → 攻击阶段（攻击方宣告攻击者和目标）
EnemyAttackPhase  → 对手攻击时阶段（防守方检查场地效果）
BlockPhase        → 防御阶段（防守方选择防御者）
BeAttackPhase     → 被攻击阶段（防守方处理被攻击效果）
CounterPhase      → 反击阶段（防守方使用带 Counter 的手牌）
DamagePhase       → 伤害结算阶段
```

### 4.2 完整战斗流程

```
攻击方（己方回合）:
  1. 选择己方场地角色卡 → AttackCard = 选中的卡
  2. 选择攻击目标（对方角色卡 或 对方领航卡）
     → DefendCard = 目标卡
  3. 调用 AttackPhase(attackCamp, attackIndex, defendIndex)
     → 攻击卡横置（攻击后状态）
     → 检查攻击时效果（EffectTime.Attack）
     → 若无效果 → 进入 EnemyAttackPhase

  敌方攻击时阶段（EnemyAttackPhase）:
  4. 防守方检查自身场地/舞台效果（EffectTime.EnemyAttack）
     → 若无效果 → 进入 BlockPhase

  防御阶段（BlockPhase）:
  5. 防守方选择防御者（ShowEnableBlockers）
     → 有防御者 → 防御者横置 → BlockAbility
     → 检查防御时效果（EffectTime.Block）
     → 若无效果 → 进入 BeAttackPhase
     → 无防御者 → 直接攻击领航卡

  被攻击阶段（BeAttackPhase）:
  6. 防守方处理被攻击时效果（EffectTime.BeAttack）
     → 若无效果 → 进入 CounterPhase

  反击阶段（CounterPhase）:
  7. 防守方选择手牌中带 Counter 值的卡
     → ShowCounterCard(true) → 可用的反击牌高亮
     → Counter 值加到 DefendCard 威力上

  伤害结算阶段（DamagePhase）:
  8. 比较攻击威力 vs 防御威力
     if (攻击威力 >= 防御威力):
       → 攻击成功
       → 若目标是领航卡：攻击方打掉对方一张生命牌
       → 若目标是角色卡：KO（进入垃圾区）
     else:
       → 防御成功（无事发生）
  9. BattleEnd → 清理 AttackCard/DefendCard → 回到主阶段
```

### 4.3 伤害方向

- **攻击领航卡成功** → 对方受到伤害（GetDamage）→ 对方领航卡生命 -1 → 如果生命为 0 则游戏结束
- **攻击角色卡成功** → 角色卡被 KO（进入垃圾区）

### 4.4 特殊机制

| 机制 | 说明 | 源码 |
|------|------|------|
| 双击（DoubleAttack） | 攻击领航卡成功时打掉 2 张生命 | `DoubleAttack` |
| 消灭（Banish） | 攻击打掉的生命直接移除（不进手牌） | `Banish` |
| 防御者（Blocker） | 有 Blocker 关键字的角色可以代为防御 | `ShowEnableBlockers()` |
| 不能攻击领航卡 | `BattleManager.CanAttackLeader` 控制 | — |
| 效果无效（EffectInvalid） | 被沉默的单位不触发效果 | `EffectInvalid` |

### 4.5 学习要点

1. 战斗是一个**线性的阶段推进**，每步都可能被效果中断
2. 攻击卡必须横置（横置后不能再次攻击同一回合）
3. 防御者也要横置
4. 反击阶段的 Counter 值来自手牌的 counter 字段，加到防御威力上
5. 攻击成功 ≠ 对方直接输，只是扣生命或 KO 角色卡
6. 效果触发时机散落在各阶段前后，如果不熟悉某个效果只需知道"可能发生"，具体由服务器裁决

## 五、生命牌机制（需重点学习）

### 5.1 生命牌数据

```csharp
// Life.cs
public List<BaseCard> LifeDeck;  // 生命牌堆（末尾为最上方）
public Sprite cardBack;          // 牌背（默认隐藏）
```

### 5.2 生命牌操作

| 操作 | 说明 | 触发时机 |
|------|------|---------|
| InitLife | 游戏开始时从卡组抽 N 张作生命牌 | 游戏初始化 |
| DrawLife | 受到伤害时从顶/底抽生命牌加入手牌 | DamagePhase |
| DrawLifeToHandByEffect | 效果触发将生命牌加入手牌 | 效果触发 |
| RemoveLife | 消灭（Banish）直接将生命牌移除 | 攻击带 Banish |
| FlipLife | 翻开/盖回生命牌 | 某些效果 |
| OpenLifeToTrash | 翻开的所有生命进垃圾区 | 效果触发 |
| GainLife | 增加生命牌 | 效果触发（回血） |
| ToDeck | 生命牌回到卡组 | 效果触发 |
| ToTrash | 生命牌进入垃圾区 | 效果触发 |

### 5.3 学习要点

1. 生命牌是**从自己的卡组抽的**，不是独立的 token
2. 受到伤害时，从生命区移除一张（默认为最上方那张）加入手牌
3. 当生命区为空（Count == 0）且再次被攻击领航卡成功时 → 游戏失败
4. 生命牌在手中可以作为普通手牌打出
5. 默认面朝下（显示牌背），某些效果可以翻开（Open）

## 六、胜利条件

### 6.1 胜负判定

```
1. 攻击领航卡成功 → GetDamage → 生命牌 -N
2. 若生命牌归零（life == 0）:
   → VictoryRequest() → 发送 MsgDefeat → 服务器判定胜负
   → DuelOver(isWin, winTips) → 显示胜负界面
```

### 6.2 其他结束条件

| 条件 | 说明 | 消息 |
|------|------|------|
| 生命归零 | 对方攻击领航卡成功且生命为 0 | `MsgDefeat` |
| 投降 | 玩家主动投降 | `MsgSurrender` |
| 断线超时 | 90 秒宽限期过后未重连 | `disconnect_timeout` |
| 卡组抽空 | 卡组为 0 时需要确认（可能判负） | 待确认 |

### 6.3 学习要点

1. `MsgDuelOver` 消息包含 `IsWin`（是否胜利）和 `Description`（胜利描述文本）
2. 注意：`GameManager.DuelOver(!isWin, ...)` —— 参数取反，因为服务器端 `IsWin` 是按发送方视角的
3. 胜利方/失败方的 UI 显示由 `ReminderType.决斗提示` 和 `GameSet.IsWin` 控制

## 七、领航卡规则

### 7.1 基本信息

- 每方**一张**领航卡，在卡组编辑时选择
- 领航卡不进入手牌/卡组，始终显示在场地侧边
- 领航卡的费用决定**初始生命牌数量**

### 7.2 领航卡特殊规则

| 规则 | 说明 |
|------|------|
| 可作为攻击目标 | `BattleManager.CanAttackLeader` 控制 |
| 效果触发时机 | TurnStart / TurnEnd / Appear 等多个时机 |
| 图片替换 | 某些效果可替换领航卡图片（`RePlaceLeaderSprite`） |
| 特殊领航卡 | 不同编号的领航卡有不同的字段效果 |

### 7.3 学习要点

1. 领航卡在 `GameManager.SetFirst()` 时特殊处理，检查是否 `OP13-079`（触发 Appear 效果而非初始抽 5 张）
2. 领航卡不参与费用、手牌、场地区
3. 领航卡也属于 `CardType.领航`，在伤害计算中有特殊处理（攻击领航卡不走 KO 流程，而是走 GetDamage → DrawLife）

## 八、效果系统概要（了解即可）

### 8.1 效果架构

```
EffectBase.cs（抽象基类）
  ↓
FieldEffectBase（场地卡效果基类）
  ↓
EffectByNum/（按编号索引的具体实现）
  ├── BE/      # 基础效果系列
  ├── CR01-CR15/  # Card Raise 系列
  ├── EB01-EB04/  # Event Base 系列
  └── P/       # 特殊系列
```

### 8.2 效果触发时机（EffectTime 枚举）

| 时机 | 说明 |
|------|------|
| `Main` | 主阶段 |
| `Counter` | 反击阶段 |
| `Trigger` | 条件触发 |
| `Attack` | 攻击时 |
| `BeAttack` | 被攻击时 |
| `EnemyAttack` | 对手攻击时 |
| `Block` | 防御时 |
| `AnyBlocker` | 任意防御者出现时 |
| `Appear` | 出场时 |
| `OnKO` | 被 K.O. 时 |
| `TurnStart` | 回合开始时 |
| `TurnEnd` | 回合结束时 |
| `Damage` | 造成伤害时 |
| `BeDamage` | 受到伤害时 |
| `OtherDamage` | 其他单位造成伤害时 |

### 8.3 效果处理模式

所有效果均通过 `RequestManager` 发送 `^` 分隔的字符串请求到服务器，服务器处理后再广播回双方客户端。客户端不自行结算效果。

### 8.4 学习要点

1. Sprint 3 **不需要**实现任何效果结算逻辑
2. 只需要知道：某张卡有 `effectEvent` 字段（如 "CR01001"），服务器会按编号调用对应效果处理器
3. 客户端需要支持的是：显示效果文本（`effectText`）和播放效果触发的动画
4. 效果可能在任何阶段触发并暂停当前流程，体现为 `EffectHandler.toHandleStack`

## 九、卡组构成规则

### 9.1 基本规则

| 规则 | 值 |
|------|-----|
| 卡组总张数 | 40 张 |
| 同名卡上限 | 4 张 |
| 领航卡 | 固定 1 张（不在 40 张内） |
| 舞台卡 | 可选，最多 1 张在场 |

### 9.2 卡牌类型（CardType）

| 类型 | 说明 | 可放置区域 |
|------|------|-----------|
| 领航（Leader） | 领袖，每方 1 张 | 场地侧边（固定） |
| 角色（Character） | 放置场地上战斗 | 场地（Field） |
| 舞台（Stage） | 提供持续效果 | 舞台区（Stage） |
| 事件（Event） | 使用后进垃圾区 | 垃圾区（Trash） |

### 9.3 卡牌颜色/属性

- **颜色**（CardColor）：炎、水、雷、风、心（可能有更多）
- **属性**（CardProperty）：斩、打、射、智、特

## 十一、鼠标/输入状态机

Unity 端使用 `Mouse.State` 控制玩家可进行的操作，Web 端需对应翻译：

| MouseState | 含义 | 允许的操作 |
|-----------|------|-----------|
| `None` | 空闲 | 点击卡牌选目标、操作费用、结束回合 |
| `Attacking` | 正在攻击 | 选择攻击目标 |
| `Blocking` | 选择防御者 | 点击防御者 |
| `BeAttacking` | 被攻击中 | 处理被攻击效果 |
| `Countering` | 选择反击牌 | 点击手牌中带 Counter 的牌 |
| `Damaging` | 伤害动画中 | 无操作 |
| `WaitingOpponent` | 等待对手 | 无操作 |
| `ShowingButton_Hand` | 手牌操作菜单 | 出牌/效果/查看 |
| `ShowingButton_Field` | 场地操作菜单 | 攻击/效果/查看 |

这对应 Web 端的 **用户交互状态机**，需要重点参考。
