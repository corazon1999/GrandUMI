# GrandUMI 新正式服迁移与回退说明

更新日期：2026-08-15

## 1. 服务器命名与入口

- **正式服**：香港 CN2 服务器 `103.146.230.37`，8 核 CPU、8 GiB 内存、75 Mbps CN2、公网双 IP、80 GiB 系统盘和 40 GiB 数据盘。
- **旧正式服**：阿里云香港服务器 `8.210.155.25`，仅用于迁移后的短期冷备和紧急回退。
- **玩家主入口**：`https://grand-umi.com`。
- **对局低延迟入口**：`wss://direct.grand-umi.com/ws`，DNS 必须独占指向新正式服 `103.146.230.37`，并使用独立有效的 TLS 证书。
- **正式服候选入口**：`candidate.grand-umi.com`，仅用于切流前验收，不作为玩家长期入口。
- `grand-umi.com` 由 Cloudflare 代理并作为 WebSocket 故障兜底；正常对局必须优先使用不经过 Cloudflare 的 `direct.grand-umi.com`。

## 2. 正式服运行架构

```text
玩家浏览器
  -> Cloudflare（DNS、TLS、静态缓存与基础防护）
  -> 新正式服 Nginx（HTTPS/WSS、反向代理、静态资源）
      -> Next.js 前端服务
      -> .NET WebSocket/HTTP 后端
      -> /data/grandumi 持久化业务数据
      -> /www/cards-* 卡图资源
```

正式服 systemd 服务：

- `grandumi-production-backend.service`
- `grandumi-production-frontend.service`
- `nginx.service`

正式服主要路径：

- 代码与发布目录：`/opt/grandumi`
- 玩家数据：`/data/grandumi`
- 卡图资源：`/www/cards-webp`、`/www/cards-thumb`
- TLS 证书：`/etc/letsencrypt/live/grand-umi.com`

后端容量保护参数：最大连接数 `3000`、最大房间数 `600`。这些数值是拒绝过载的安全上限，不代表无需压测即可保证相同规模；500 个活跃房间上线前仍应完成分阶段压测。

## 4. 日常健康检查

外网检查：

```bash
curl -fsS https://grand-umi.com/backend/version
curl -fsS https://grand-umi.com/backend/ready
curl -fsS https://direct.grand-umi.com/backend/version
curl -fsS https://direct.grand-umi.com/backend/ready
curl -I https://grand-umi.com/home
curl -I https://grand-umi.com/cards-webp/prb02/PRB02-003.webp
```

两个域名的 `/backend/version` 必须返回同一正式服提交与节点；`/backend/ready` 应返回 `status: ready` 且 `overloaded: false`。还需从浏览器确认实际首选连接为 `wss://direct.grand-umi.com/ws`，Cloudflare 的 `wss://grand-umi.com/ws` 只在直连失败时兜底。

迁移或回退前必须先完成直连域名切换、证书签发和 WebSocket RTT 验收，再允许发布脚本生成直连优先的运行时清单。旧服务器完成排空后必须保持业务后端停止，避免旧直连 DNS、浏览器缓存或失败回退把玩家带到另一套可写数据库。

服务器检查：

```bash
systemctl status grandumi-production-backend grandumi-production-frontend nginx
journalctl -u grandumi-production-backend --since "30 minutes ago" --no-pager
df -h / /data /www
```

## 5. 回退原则与步骤

回退不是单纯改 DNS。新正式服切流后可能已经产生新的注册、卡组、排位和对局数据；若直接启动旧正式服，会丢失切流后的玩家进度。因此先判断是否需要保留新数据。

### 5.1 不保留切流后数据的紧急回退

仅适用于刚切流且确认没有需要保留的新数据：

1. 在 Cloudflare 将根域名 `grand-umi.com` 的 A 记录改回 `8.210.155.25`，保持原代理状态。
2. 在旧正式服确认出口限速仍为 `2mbit`，再启动 `grandumi-backend.service` 与 `grandumi-frontend.service`。
3. 等待 Cloudflare 生效，并检查版本、就绪接口、网页、卡图和 WSS。
4. 停止新正式服业务服务，避免玩家被分流到两套可写数据源。

### 5.2 需要保留切流后数据的回退

1. 先开启维护状态，等待现有对局自然结束，再停止新正式服后端写入。
2. 对新正式服三个 SQLite 数据库执行在线安全备份，并完成 `PRAGMA integrity_check`。
3. 将最终数据和必要资源反向同步到旧正式服，先落入独立暂存目录并校验哈希。
4. 备份旧正式服现有数据后再原子替换。
5. 启动旧正式服并通过候选域名或本机 Host 映射验收。
6. 最后修改 Cloudflare DNS，确认公网已回到旧节点后再结束维护。

任何情况下都不得让两台正式服同时对同一玩家数据提供写服务。

## 6. 证书与后续工作

当前 `grand-umi.com` 证书有效期至 **2026-11-13**，本次证书为手工签发，尚未实现无人值守自动续期。应在到期前至少 30 天使用 Cloudflare 最小权限 API Token 配置 DNS-01 自动续期，并进行一次模拟续期验证。

稳定观察期建议至少 7 天。观察期间重点记录：全服断线次数、WebSocket 重连率、P95/P99 延迟、出口带宽峰值、CPU、内存、房间数和连接数。确认新正式服稳定且备份可恢复后，再决定旧正式服的下线时间。
