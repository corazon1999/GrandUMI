## 一、重构原则

1. **服务器零逻辑改动** — 仅新增 WebSocket 端点，协议/消息格式不变
2. **数据资源零迁移** — 所有 JSON 卡牌数据、图片资源直接复用
3. **模块映射翻译** — 逐模块对照 C# 翻译为 TypeScript，不重新设计
4. **分阶段可交付** — 每个 Sprint 结束产出可运行的功能模块
5. **Effect 渐进移植** — 效果系统按卡集批次移植，不阻塞主线上线

## 四、服务器端改动（最小）

### 4.1 改动范围

现有 C# 服务器**不修改任何游戏逻辑**，仅新增 WebSocket 接入点：

```csharp
// 在现有 Server 启动代码中新增（约 50 行）
// 原 TCP 监听保留，新增 WebSocket 监听

using System.Net.WebSockets;

public class WebSocketEndpoint
{
    private static readonly Dictionary<string, WebSocket> _clients = new();

    public static async Task HandleWebSocket(HttpContext ctx)
    {
        if (!ctx.WebSockets.IsWebSocketRequest) { ctx.Response.StatusCode = 400; return; }

        var ws = await ctx.WebSockets.AcceptWebSocketAsync();
        var clientId = Guid.NewGuid().ToString();
        _clients[clientId] = ws;

        // 接收消息 → 转发给现有协议处理器（复用原逻辑）
        await ReceiveLoop(ws, clientId);
    }

    private static async Task ReceiveLoop(WebSocket ws, string clientId)
    {
        var buffer = new byte[4096];
        while (ws.State == WebSocketState.Open)
        {
            var result = await ws.ReceiveAsync(buffer, CancellationToken.None);
            if (result.MessageType == WebSocketMessageType.Text)
            {
                var json = Encoding.UTF8.GetString(buffer, 0, result.Count);
                var msg = JsonConvert.DeserializeObject<MsgBase>(json);
                // 直接复用现有协议分发逻辑
                ProtocolHandler.Dispatch(clientId, msg);
            }
        }
        _clients.Remove(clientId);
    }

    // 供现有游戏逻辑调用，向 WebSocket 客户端发送消息
    public static async Task SendToClient(string clientId, MsgBase msg)
    {
        if (_clients.TryGetValue(clientId, out var ws))
        {
            var json = JsonConvert.SerializeObject(msg);
            var bytes = Encoding.UTF8.GetBytes(json);
            await ws.SendAsync(bytes, WebSocketMessageType.Text, true, CancellationToken.None);
        }
    }
}
```

### 4.2 服务器安全实现

在 WebSocket 端点基础上新增三个安全模块，**不修改任何原有游戏逻辑**。

**`ServerKeyManager.cs`** — RSA 密钥管理（解决 S1）

```csharp
using System.Security.Cryptography;

public static class ServerKeyManager
{
    private static RSACryptoServiceProvider _rsa;
    public static string PublicKeyXml { get; private set; }

    // 服务器启动时调用一次，私钥只存内存
    public static void Initialize()
    {
        _rsa = new RSACryptoServiceProvider(2048);
        PublicKeyXml = _rsa.ToXmlString(includePrivateParameters: false);
    }

    public static byte[] DecryptSessionKey(byte[] encryptedKey) =>
        _rsa.Decrypt(encryptedKey, fOAEP: true);
}
```

**`SessionManager.cs`** — 会话 Token 生命周期（解决 S5）

```csharp
using System.Collections.Concurrent;
using System.Security.Cryptography;

public static class SessionManager
{
    private static readonly ConcurrentDictionary<string, SessionEntry> _byClient = new();
    private static readonly ConcurrentDictionary<string, string> _tokenIndex = new();

    public static string CreateSession(string clientId, string accountId)
    {
        byte[] raw = new byte[32];
        RandomNumberGenerator.Fill(raw);
        string token = Convert.ToBase64String(raw);

        _byClient[clientId] = new SessionEntry
        {
            Token     = token,
            AccountId = accountId,
            ExpireAt  = DateTime.UtcNow.AddHours(24),
        };
        _tokenIndex[token] = clientId;
        return token;
    }

    // 验证 token，返回 accountId；失败返回 null
    public static string Validate(string token)
    {
        if (!_tokenIndex.TryGetValue(token, out var cid)) return null;
        if (!_byClient.TryGetValue(cid, out var e))      return null;
        if (e.ExpireAt < DateTime.UtcNow) { Revoke(token); return null; }
        return e.AccountId;
    }

    public static void Revoke(string token)
    {
        if (_tokenIndex.TryRemove(token, out var cid))
            _byClient.TryRemove(cid, out _);
    }

    private record SessionEntry(string Token, string AccountId, DateTime ExpireAt);
}
```

**修改 `WebSocketEndpoint.ReceiveLoop`** — 分发前统一鉴权

```csharp
private static readonly HashSet<int> _noAuthProtos = new()
{
    (int)ProtocolEnum.MsgHandshake,
    (int)ProtocolEnum.MsgSecret,
    (int)ProtocolEnum.MsgLogin,
    (int)ProtocolEnum.MsgAddAccount,
    (int)ProtocolEnum.MsgPing,
};

private static async Task ReceiveLoop(WebSocket ws, string clientId)
{
    var buffer = new byte[4096];
    while (ws.State == WebSocketState.Open)
    {
        var result = await ws.ReceiveAsync(buffer, CancellationToken.None);
        if (result.MessageType != WebSocketMessageType.Text) continue;

        var json = Encoding.UTF8.GetString(buffer, 0, result.Count);
        var msg  = JsonConvert.DeserializeObject<MsgBase>(json);

        // 鉴权中间件
        if (!_noAuthProtos.Contains(msg.protoNo))
        {
            var token = (msg as dynamic)?.sessionToken as string;
            if (SessionManager.Validate(token) == null)
            {
                await SendToClient(clientId, new { protoNo = (int)ProtocolEnum.MsgAuthError,
                                                   reason  = "token无效，请重新登录" });
                continue;
            }
        }

        // 握手处理
        if (msg.protoNo == (int)ProtocolEnum.MsgHandshake)
        {
            await SendToClient(clientId,
                new { protoNo = (int)ProtocolEnum.MsgHandshake,
                      publicKeyXml = ServerKeyManager.PublicKeyXml });
            continue;
        }

        // MsgSecret：解密客户端 RSA 加密的 AES 会话密钥
        if (msg.protoNo == (int)ProtocolEnum.MsgSecret)
        {
            var encKey = Convert.FromBase64String((msg as dynamic).encryptedKey as string);
            var aesKey = ServerKeyManager.DecryptSessionKey(encKey);
            WsSessionKeys[clientId] = aesKey; // 存储该连接的 AES 密钥
            await SendToClient(clientId, new { protoNo = (int)ProtocolEnum.MsgSecret, result = true });
            continue;
        }

        // MsgLogin：密码校验 + 下发 token（解决 S2/S5）
        if (msg.protoNo == (int)ProtocolEnum.MsgLogin)
        {
            var loginMsg = (msg as dynamic);
            bool ok = AccountDB.Verify(loginMsg.account as string, loginMsg.password as string);
            if (ok)
            {
                string token = SessionManager.CreateSession(clientId, loginMsg.account as string);
                await SendToClient(clientId, new
                {
                    protoNo      = (int)ProtocolEnum.MsgLogin,
                    result       = true,
                    name         = AccountDB.GetName(loginMsg.account as string),
                    sessionToken = token,
                });
            }
            else
            {
                await SendToClient(clientId, new
                {
                    protoNo = (int)ProtocolEnum.MsgLogin,
                    result  = false,
                    logStr  = "账号或密码错误",
                });
            }
            continue;
        }

        // 其余消息复用原有协议分发逻辑
        ProtocolHandler.Dispatch(clientId, msg);
    }
    _clients.Remove(clientId);
}
```

### 4.3 消息格式约定

WebSocket 消息统一使用 JSON，完整握手流程：

```
1. 客户端连接 WS
2. 客户端 → { "protoNo": 27 }                          // MsgHandshake 请求公钥
3. 服务器 → { "protoNo": 27, "publicKeyXml": "..." }   // 下发 RSA 公钥
4. 客户端  生成随机 AES 会话密钥，RSA-OAEP 加密
5. 客户端 → { "protoNo": 1, "encryptedKey": "base64" } // MsgSecret 上传加密密钥
6. 服务器 → { "protoNo": 1, "result": true }           // 握手完成
7. 客户端 → { "protoNo": 18, "account": "x", "password": "sha256hash" } // 登录
8. 服务器 → { "protoNo": 18, "result": true, "sessionToken": "token" }  // 下发 token
9. 后续消息均携带 sessionToken 字段
```

游戏动作示例：

```json
{
  "protoNo": 26,
  "sessionToken": "abc123...",
  "action": "PlayCard",
  "data": { "handIndex": 2 }
}
```

**`types/net.ts`** — 对应 Proto/ 目录

```typescript
export enum ProtocolEnum {
  None = 0,
  MsgSecret = 1,
  MsgPing = 2,
  MsgCreateRoom = 3,
  MsgGetRoomList = 4,
  MsgEnterRoom = 7,
  MsgPrepare = 9,
  MsgGameStart = 10,
  MsgShuffle = 11,
  MsgChatMsg = 14,
  MsgTransmit = 15,
  MsgLogin = 18,
  MsgAddAccount = 20,
  // 服务端结算架构
  MsgGameState = 25,
  MsgGameAction = 26,
  // 安全握手
  MsgHandshake = 27,    // RSA 公钥交换（S1）
  MsgAuthError = 28,    // 服务器：token 验证失败通知（S5）
}

export interface MsgBase {
  protoNo: ProtocolEnum
  sessionToken?: string  // 登录后所有消息携带（S5），握手/登录消息除外
}

export interface MsgHandshake extends MsgBase {
  protoNo: ProtocolEnum.MsgHandshake
  publicKeyXml?: string  // 服务器响应时填入 RSA 公钥
}

export interface MsgSecret extends MsgBase {
  protoNo: ProtocolEnum.MsgSecret
  encryptedKey?: string  // 客户端：RSA-OAEP 加密后的 AES 会话密钥（Base64）
  result?: boolean       // 服务器：握手成功
}

export interface MsgLogin extends MsgBase {
```

### 5.2 网络层（net/）

**`net/NetManager.ts`** — 对应 `NetManager.cs`，含 RSA 握手 + Token 注入

```typescript
import mitt, { Emitter } from 'mitt'
import { MsgBase, MsgHandshake, MsgSecret, ProtocolEnum } from '@/types/net'

type NetEvents = {
  connectSucc: void   // 握手+密钥交换全部完成后才触发
  connectFail: void
  close: void
  message: MsgBase
}

// 无需 token 的协议号白名单
const NO_AUTH_PROTOS = new Set([
  ProtocolEnum.MsgHandshake,
  ProtocolEnum.MsgSecret,
  ProtocolEnum.MsgLogin,
  ProtocolEnum.MsgAddAccount,
  ProtocolEnum.MsgPing,
])

class NetManagerClass {
  private ws: WebSocket | null = null
  private pingTimer: ReturnType<typeof setInterval> | null = null
  private msgQueue: MsgBase[] = []
  private sessionToken: string | null = null  // 内存存储，不写 localStorage（S5）
  readonly emitter: Emitter<NetEvents> = mitt()

  // 连接后自动完成 RSA 握手，握手成功才 emit connectSucc（S1）
  connect(url: string) {
    this.ws = new WebSocket(url)

    this.ws.onopen = () => {
      this.startHandshake()  // 连接后立即握手，不直接 emit connectSucc
    }

    this.ws.onclose = () => {
      this.stopHeartbeat()
      this.sessionToken = null
      this.emitter.emit('close')
    }

    this.ws.onerror = () => this.emitter.emit('connectFail')

    this.ws.onmessage = (e) => {
      const msg: MsgBase = JSON.parse(e.data)
      this.msgQueue.push(msg)
      this.processQueue()
    }
  }

  // 握手流程：请求公钥 → 生成 AES 密钥 → RSA 加密上传（S1）
  private async startHandshake() {
    this.sendRaw({ protoNo: ProtocolEnum.MsgHandshake })

    // 等待服务器返回 RSA 公钥
    const handshakeMsg = await this.waitForProto(ProtocolEnum.MsgHandshake) as MsgHandshake

    // 生成随机 32 字节 AES 会话密钥
    const aesKeyBytes = crypto.getRandomValues(new Uint8Array(32))

    // RSA-OAEP 加密
    const publicKey = await crypto.subtle.importKey(
      'spki',
      this.pemToDer(handshakeMsg.publicKeyXml!),
      { name: 'RSA-OAEP', hash: 'SHA-256' },
      false,
      ['encrypt']
    )
    const encryptedKey = await crypto.subtle.encrypt(
      { name: 'RSA-OAEP' },
      publicKey,
      aesKeyBytes
    )

    this.sendRaw({
      protoNo: ProtocolEnum.MsgSecret,
      encryptedKey: btoa(String.fromCharCode(...new Uint8Array(encryptedKey))),
    } as MsgSecret)

    // 等待握手确认
    await this.waitForProto(ProtocolEnum.MsgSecret)

    // 握手完成，启动心跳，通知上层
    this.startHeartbeat()
    this.emitter.emit('connectSucc')
  }

  // send：白名单外的消息自动注入 sessionToken（S5）
  send(msg: MsgBase) {
    if (this.ws?.readyState !== WebSocket.OPEN) return
    const payload = NO_AUTH_PROTOS.has(msg.protoNo)
      ? msg
      : { ...msg, sessionToken: this.sessionToken }
    this.ws.send(JSON.stringify(payload))
  }

  // sendRaw：握手阶段专用，不注入 token
  private sendRaw(msg: MsgBase) {
    if (this.ws?.readyState === WebSocket.OPEN)
      this.ws.send(JSON.stringify(msg))
  }

  setSessionToken(token: string) { this.sessionToken = token }
  clearSession()                 { this.sessionToken = null }

  private processQueue() {
    while (this.msgQueue.length > 0) {
      const msg = this.msgQueue.shift()!
      this.emitter.emit('message', msg)
    }
  }

  // 等待指定协议号的第一条消息（握手用）
  private waitForProto(protoNo: ProtocolEnum): Promise<MsgBase> {
    return new Promise((resolve) => {
      const handler = (msg: MsgBase) => {
        if (msg.protoNo === protoNo) {
          this.emitter.off('message', handler)
          resolve(msg)
        }
      }
      this.emitter.on('message', handler)
    })
  }

  private pemToDer(pem: string): ArrayBuffer {
    // 服务器下发的是 XML 格式，需在服务器侧转为标准 PEM 再下发
    // 或客户端用库解析 XML 公钥；此处假设服务器已转为 Base64 DER
    const b64 = pem.replace(/-----.*?-----|\s/g, '')
    const bin = atob(b64)
    const buf = new Uint8Array(bin.length)
    for (let i = 0; i < bin.length; i++) buf[i] = bin.charCodeAt(i)
    return buf.buffer
  }

  private startHeartbeat() {
    this.pingTimer = setInterval(() => {
      this.send({ protoNo: ProtocolEnum.MsgPing })
    }, 10_000)  // 对战中 10 秒心跳（原 30 秒过长）
  }

  private stopHeartbeat() {
    if (this.pingTimer) { clearInterval(this.pingTimer); this.pingTimer = null }
  }

  disconnect() { this.ws?.close() }
}

export const NetManager = new NetManagerClass()
```

```typescript
// SHA-256 密码哈希，使用 Web Crypto API（S2）
async function hashPassword(plain: string): Promise<string> {
  const salted = 'OPCG:' + plain  // 应用级前缀防止彩虹表复用
  const buf = await crypto.subtle.digest(
    'SHA-256',
    new TextEncoder().encode(salted)
  )
  return btoa(String.fromCharCode(...new Uint8Array(buf)))
}
```

### 5.3 状态管理（store/）

> **架构原则**：store 是只读镜像，唯一写入来源是 `syncFromServer`。  
> 客户端不持有任何结算逻辑——`nextTurn / playToField / tapCard / applyBuff / takeDamage` 等方法**全部删除**，由服务器结算后推送结果。
>
> **A4 修复说明**：原方案的 `syncFromServer: (state) => set((s) => Object.assign(s, state))` 会绕过 immer 的 Proxy 追踪，导致 immer 无法生成 patch、所有订阅组件强制重渲染。  
> 现改为逐字段赋值（`s.phase = msg.phase` 等），immer 能精确追踪变更字段，只有订阅了变更字段的组件才会重渲染。

**`store/gameStore.ts`** — 纯状态镜像，对应 `GameManager.cs`

```typescript

import { immer } from 'zustand/middleware/immer'

  phase: string
  currentTurn: boolean
  turnCount: number
  my: PlayerState
  opponent: PlayerState

  // ---- 动画驱动字段（由 lastAction 触发，不影响结算） ----
  lastAction: string
  lastActionPayload: unknown

  // ---- 请求锁（发出 action 到收到回包之间禁止操作） ----
  isPending: boolean

  // ---- 唯一写入入口 ----
  syncFromServer: (msg: MsgGameState) => void

  // ---- 纯 UI 选中状态（不上报服务器） ----
  selectedHandIndex: number | null
  selectedFieldIndex: number | null

  setSelectedField: (index: number | null) => void

    phase: 'Main',
    currentTurn: false,
    turnCount: 0,
    lastAction: '',
    lastActionPayload: null,
    isPending: false,
    selectedHandIndex: null,
    selectedFieldIndex: null,
    my: emptyPlayerState(),
    opponent: emptyPlayerState(),

    // 收到服务器推送 → 整体覆盖，清除选中和 pending

      s.currentTurn = msg.currentTurn

      s.selectedFieldIndex = null

    }),

    setSelectedHand: (index) => set((s) => { s.selectedHandIndex = index }),
    setSelectedField: (index) => set((s) => { s.selectedFieldIndex = index }),
    setPending: (v) => set((s) => { s.isPending = v }),
  }))

function snapshotToPlayerState(snap: PlayerSnapshot, isMe: boolean): PlayerState {
  return {
    cost: { active: snap.costActive, max: snap.costMax, zone: [] },
    hand: {
      // 己方有完整卡牌数据；对手只有数量（显示牌背，card 为 null）

        ? snap.handCardNumbers.map((n) => getCard(n)).filter(Boolean) as CardData[]
        : Array<null>(snap.handCount).fill(null) as unknown as CardData[],
      canChoose: false,
    },
    field: {
      characterCards: snap.fieldCards.map((fc: FieldCardSnapshot): FieldCardState => ({
        card: getCard(fc.number)!,
        isTapped: fc.isTapped,
        powerBuff: fc.powerBuff,
        isSelected: false,
      })),
      stageCard: snap.stageNumber ? (getCard(snap.stageNumber) ?? null) : null,
      isMyTurn: false,
    },
    deckCount: snap.deckCount,
    life: Array<null>(snap.lifeCount).fill(null) as unknown as CardData[],
    leader: snap.leaderNumber ? (getCard(snap.leaderNumber) ?? null) : null,
  }
}

function emptyPlayerState(): PlayerState {
  return {
    cost: { active: 0, max: 0, zone: [] },
    hand: { cards: [], canChoose: false },
    field: { characterCards: [], stageCard: null, isMyTurn: false },
    deckCount: 50,
    life: [],
    leader: null,
  }
}
```

### 5.8 断线重连机制（A8 修复）

断线重连是实时对战的基础可靠性保障。整个方案分为四层：**服务器宽限期 → 客户端状态机 → 重连 UI → 状态恢复**。

#### 5.8.1 数据流与状态机

```
正常游戏
  ↓  网络中断
RECONNECTING（指数退避自动重试）
  ↓  WS 重新建立
HANDSHAKING（重走 RSA 握手，生成新会话密钥）
  ↓  握手完成
RE_AUTHING（用旧 sessionToken 向服务器证明身份）
  ↓  token 有效（服务器宽限期内）
RECOVERING（请求当前完整游戏快照 MsgRequestState）
  ↓  收到 MsgGameState
CONNECTED（游戏恢复，同步到最新状态）

RECONNECTING 超过最大重试次数 → FAILED（弹出"游戏结束"）
RE_AUTHING token 无效（超过宽限期）→ FAILED
```

**`GameRoomManager.cs`**（新增宽限期逻辑）

```csharp
public static class GameRoomManager
{
    // token → 房间绑定（重连身份核验用）
    private static readonly ConcurrentDictionary<string, string> _tokenToRoom = new();
    // 房间 → 断线计时器
    private static readonly ConcurrentDictionary<string, CancellationTokenSource> _gracePeriods = new();

    private const int GracePeriodSeconds = 90; // 宽限期：90 秒内可重连

    // 玩家登录/进入房间时绑定
    public static void BindTokenToRoom(string sessionToken, string roomId)
        => _tokenToRoom[sessionToken] = roomId;

    // 客户端断线时调用
    public static void OnPlayerDisconnect(string clientId, string sessionToken)
    {
        if (!_tokenToRoom.TryGetValue(sessionToken, out var roomId)) return;

        // 通知对手
        var opponentId = GetOpponentId(roomId, clientId);
        if (opponentId != null)
        {
            _ = WebSocketEndpoint.SendToClient(opponentId, new MsgPlayerDisconnected
            {
                protoNo           = (int)ProtocolEnum.MsgPlayerDisconnected,
                gracePeriodSeconds = GracePeriodSeconds,
            });
        }

        // 启动宽限期计时器，超时后判负
        var cts = new CancellationTokenSource();
        _gracePeriods[roomId] = cts;
        _ = Task.Delay(TimeSpan.FromSeconds(GracePeriodSeconds), cts.Token)
                .ContinueWith(t =>
                {
                    if (!t.IsCanceled) ForceGameOver(roomId, clientId, "disconnect_timeout");
                });
    }

    // 客户端重连后调用
    public static bool OnPlayerReconnect(string newClientId, string sessionToken)
    {
        if (!_tokenToRoom.TryGetValue(sessionToken, out var roomId)) return false;

        // 取消超时判负
        if (_gracePeriods.TryRemove(roomId, out var cts)) cts.Cancel();

        // 通知对手恢复
        var opponentId = GetOpponentId(roomId, newClientId);
        if (opponentId != null)
        {
            _ = WebSocketEndpoint.SendToClient(opponentId, new MsgPlayerReconnected
            {
                protoNo = (int)ProtocolEnum.MsgPlayerReconnected
            });
        }
        return true;
    }
}
```

#### 5.8.4 客户端 NetManager 重连状态机

**在 `NetManager.ts` 中新增重连逻辑**

```typescript
type ConnectPhase =
  | 'idle'
  | 'connecting'
  | 'handshaking'
  | 'ready'
  | 'reconnecting'
  | 'recovering'
  | 'failed'

// 指数退避延迟（ms）
const BACKOFF = [1_000, 2_000, 4_000, 8_000, 15_000]

class NetManagerClass {
  // ...（原有字段）
  private phase: ConnectPhase = 'idle'
  private reconnectAttempt   = 0
  private wsUrl              = ''

  connect(url: string) {
    this.wsUrl = url
    this.reconnectAttempt = 0
    this._connect()
  }

  private _connect() {
    this.phase = this.reconnectAttempt === 0 ? 'connecting' : 'reconnecting'
    useNetStore.getState().setConnStatus(this.phase)

    this.ws = new WebSocket(this.wsUrl)
    this.ws.onopen  = () => this.startHandshake()
    this.ws.onerror = () => this.scheduleReconnect()
    this.ws.onclose = () => {
      this.stopHeartbeat()
      if (this.phase === 'ready' && this.sessionToken) {
        // 在线时意外断线 → 尝试重连
        this.scheduleReconnect()
      } else {
        this.phase = 'idle'
        useNetStore.getState().setConnStatus('idle')
        this.emitter.emit('close')
      }
    }
    this.ws.onmessage = (e) => {
      const msg: MsgBase = JSON.parse(e.data)
      this.msgQueue.push(msg)
      this.processQueue()
    }
  }

  private async startHandshake() {
    this.phase = 'handshaking'
    // ...（原握手流程不变）
    // 握手完成后：
    this.phase = 'ready'

    if (this.reconnectAttempt > 0) {
      // 重连场景：跳过登录，直接请求恢复状态
      await this.recoverSession()
    } else {
      this.reconnectAttempt = 0
      this.startHeartbeat()
      this.emitter.emit('connectSucc')
    }
  }

  // 重连后用旧 token 恢复游戏状态
  private async recoverSession() {
    this.phase = 'recovering'
    useNetStore.getState().setConnStatus('recovering')
    this.sendRaw({
      protoNo:      ProtocolEnum.MsgRequestState,
      sessionToken: this.sessionToken!,
    } as MsgRequestState)
    // 后续由 GameProtocol 处理收到的 MsgGameState，自动调用 syncFromServer
    this.reconnectAttempt = 0
    this.startHeartbeat()
    // 不 emit connectSucc，只 emit reconnected
    this.emitter.emit('reconnected')
    useNetStore.getState().setConnStatus('ready')
  }

  private scheduleReconnect() {
    if (this.reconnectAttempt >= BACKOFF.length) {
      this.phase = 'failed'
      useNetStore.getState().setConnStatus('failed')
      this.emitter.emit('reconnectFailed')
      return
    }
    const delay = BACKOFF[this.reconnectAttempt++]
    useNetStore.getState().setConnStatus('reconnecting')
    useNetStore.getState().setReconnectCountdown(delay / 1000)
    setTimeout(() => this._connect(), delay)
  }
}
```

#### 5.8.6 重连遮罩组件（`components/game/ReconnectOverlay.tsx`）

在游戏中断线时全屏遮罩，阻止用户操作，显示重连进度。

```tsx
'use client'

import { useEffect, useRef } from 'react'
import { useNetStore } from '@/store/netStore'
import { motion, AnimatePresence } from 'framer-motion'

export default function ReconnectOverlay() {
  const { connStatus, reconnectCountdown } = useNetStore()
  const timerRef = useRef<ReturnType<typeof setInterval> | null>(null)
  const [remaining, setRemaining] = useStateRef(reconnectCountdown)

  // 收到新倒计时时启动本地秒级递减
  useEffect(() => {
    if (connStatus !== 'reconnecting') return
    setRemaining(reconnectCountdown)
    timerRef.current = setInterval(() => setRemaining((n) => Math.max(0, n - 1)), 1000)
    return () => { if (timerRef.current) clearInterval(timerRef.current) }
  }, [reconnectCountdown])

  const visible = connStatus === 'reconnecting' || connStatus === 'recovering'

  return (
    <AnimatePresence>
      {visible && (
        <motion.div
          className="fixed inset-0 z-50 flex flex-col items-center justify-center bg-black/80 backdrop-blur-sm"
          initial={{ opacity: 0 }} animate={{ opacity: 1 }} exit={{ opacity: 0 }}

          <div className="w-12 h-12 border-4 border-orange-400 border-t-transparent rounded-full animate-spin mb-4" />
```

**`server.ts`**（A2 修复：开发环境 WebSocket 代理，生产不使用）

```typescript
// 仅开发环境生效，package.json dev 脚本改为 `ts-node server.ts`
import { createServer } from 'http'
import { parse } from 'url'
import next from 'next'
import { createProxyServer } from 'http-proxy'

const dev   = process.env.NODE_ENV !== 'production'
const app   = next({ dev })
const proxy = createProxyServer({ target: 'ws://localhost:8080', ws: true })

app.prepare().then(() => {
  const handle = app.getRequestHandler()

  const server = createServer((req, res) => {
    handle(req, res, parse(req.url!, true))
  })

  // WS 升级请求转发给后端（HTTP 的 upgrade 事件）
  server.on('upgrade', (req, socket, head) => {
    if (req.url?.startsWith('/ws')) {
      proxy.ws(req, socket, head)
    }
  })

  server.listen(3000, () => console.log('> Ready on http://localhost:3000'))
})
```

> 生产环境：前端直接连 `wss://<server-domain>/ws`，不需要代理。

### 10.3 结算架构约定

```
禁止在客户端 store 中直接修改游戏状态字段：
  ✗  useGameStore.getState().my.hand.cards.push(card)
  ✗  gameStore 内除 syncFromServer 以外的任何 set 逻辑影响游戏状态

所有游戏操作必须经由 GameRequest 发送：
  ✓  GameRequest.playCard(index)
  ✓  GameRequest.attack(attackerIndex, target)

收到 MsgGameState 后才更新 store，动画由 lastAction 驱动：
  ✓  syncFromServer(msg) → 更新状态 → 组件 useEffect 监听 lastAction → 播放动画
```

## 十三、已知问题与漏洞分析

### 13.1 安全漏洞

| 编号 | 位置 | 问题 | 风险等级 | 修复建议 |
|------|------|------|----------|---------|
| S1 | `AES.cs` + 握手协议 | 握手公钥 `"GrandUMIServer"` 硬编码在客户端，任何人反编译 Unity 包即可拿到 | 高 | 改为非对称加密（RSA）完成密钥交换，服务器持有私钥 |
| S2 | `StreamingAssets/Account.json` | 账户数据文件随包分发，玩家可直接读取 | 高 | 账户信息只存服务器，本地只缓存 session token |
| S3 | 原方案客户端结算 | 双方各自算结算，可被修改内存伪造结果 | 严重 | **已通过服务端结算方案修复** |
| S4 | `StreamingAssets/Data/` JSON | 卡牌数据在本地，玩家可篡改 effectEvent 编号 | 中 | 服务器使用自有卡牌数据库，不信任客户端卡牌数据；客户端 JSON 仅用于展示 |
| S5 | WebSocket 无认证 token | 连接建立后发送的 `MsgGameAction` 没有会话凭证，无法防止会话劫持 | 高 | 登录成功后服务器下发 session token，后续每条消息携带 token 验证 |
| S6 | `public/sprites/` 路径可预测 | 所有卡图路径 `/sprites/OP01/OP01-001.png` 规律可循，可被批量爬取 | 低 | 可接受（卡图属于公开资产）；若需保护可加 CDN 签名 |

### 13.2 架构缺陷

| 编号 | 位置 | 问题 | 影响 |
|------|------|------|------|
| A1 | `NetManager.ts`（模块级单例） | 模块在浏览器中是单例，页面刷新后 WebSocket 实例丢失，不会自动重连 | 刷新后需重新登录（待处理） |
| A2 ✅ | `next.config.ts` rewrites | Next.js `rewrites` 不支持 WebSocket 协议升级，开发环境 WS 连接失败 | **已修复**：改用自定义 `server.ts` + `http-proxy` 代理 `/ws` |
| A3 ✅ | `app/layout.tsx` 预加载 | `preloadAllCardSets()` 在服务端组件中调用，fetch 相对路径失败 | **已修复**：移入 `ClientProvider.tsx` 客户端组件的 `useEffect` |
| A4 ✅ | `syncFromServer` 使用 `Object.assign` | 绕过 immer Proxy 追踪，所有组件强制重渲染 | **已修复**：改为逐字段赋值，immer 精确追踪变更字段 |
| A5 ✅ | `MsgTransmit.action` 为裸字符串 | 游戏动作无类型约束，协议不一致无法在编译期发现 | **已修复**：改为 `MsgGameAction.action: GameActionType` |
| A6 ✅ | 心跳间隔 30 秒 | 对战中网络中断最多 30 秒后才发现 | **已修复**：改为 10 秒 |
| A7 | `EventCenter` 内存泄漏风险 | C# 端若 `OnDestroy` 未调用 `RemoveListener`，回调永久存活 | Unity 端需在 `OnDestroy` 中统一清理（待处理） |
| A8 ✅ | 断线重连无状态恢复 | 断线即等同于游戏结束，体验极差 | **已修复**：指数退避重连 + 90 秒宽限期 + `MsgRequestState` 恢复快照（见 5.8） |
| A9 | `PlaybackManager` 在客户端录制 | 回放数据在本地生成，玩家可篡改录像 | 录制应在服务器端（待处理） |
| A10 | `deckStore` 保存到 `localStorage` | 多端不同步，无法防止违规卡组 | 卡组保存到服务器，下发时做合法性校验（待处理） |

### 13.3 协议设计问题

| 编号 | 问题 | 修复建议 |
|------|------|---------|
| P1 | 无协议版本号 | 握手时交换 `clientVersion`，不匹配时服务器主动断开并提示更新 |
| P2 | 无消息序列号 | 添加 `seq: number`，服务器检测乱序/重复消息 |
| P3 | `MsgGameAction` 无服务器端验证描述 | 服务器收到每个 action 必须校验：是否轮到该玩家、费用是否足够、目标是否合法 |
