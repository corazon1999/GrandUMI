# s-蛇、s-鹰、s-鲨上线清单

本清单只描述可回滚的 QQ 助理启用流程，不构成任何正式服、候选服或游戏服务部署授权。
在 `s-鹰`、`s-鲨` 的登录条件齐备前，代码可以部署，但两个连接必须保持 `enabled=false`。

## 一、上线前必须具备

- 三个固定账号分别为 `s-蛇 3215228879`、`s-鹰 3430685803`、`s-鲨 184689168`；
  上线前再次确认群昵称与账号完全对应。
- 两个账号均已加入目标群；管理员 QQ 固定为 `651846226`，不得通过配置改成其他账号。
- 能通过仅绑定本机的 SSH 隧道访问 `6100`、`6101` 两个 NapCat WebUI 并完成扫码或
  设备确认。登录二维码、Cookie、密码摘要和访问令牌不得提交到仓库或粘贴到日志。
- 为两个 OneBot 正向 WebSocket 分别生成随机长令牌。令牌只写服务器权限为 `640` 的
  `config.server.json` 和对应 NapCat 私有配置。
- 确认服务器已有足够空间备份 `s-蛇` 的三组现有卷和两个新账号的六组独立卷；任何
  账号都不得挂载另一个账号的 QQ、NapCat 配置或插件卷。

## 二、先建立隔离登录态

1. 在私有 `.env` 中填写 `NAPCAT_EAGLE_ACCOUNT`、`NAPCAT_SHARK_ACCOUNT`，核对三套
   `HOSTNAME` 与 `MAC_ADDRESS` 均不同且以后保持不变。
2. 保持 `config.server.json` 中两个副助理 `enabled=false`，只启动接入端：

   ```bash
   docker compose up -d napcat-eagle napcat-shark
   ```

3. 分别建立 SSH 隧道并打开 WebUI：

   ```powershell
   ssh -L 6100:127.0.0.1:6100 -L 6101:127.0.0.1:6101 root@服务器地址
   ```

4. 每个账号都单独扫码登录，单独新增监听 `0.0.0.0:3001` 的正向 WebSocket 服务端，
   填写各自令牌。不得把 WebUI 配置或 OneBot 配置复制进另一个账号的登录卷。
5. 分别从对应 OneBot 调用 `get_login_info`，确认返回 QQ 与配置中的 `expected_self_id`
   完全一致。副助理缺少该字段会在启动时失败关闭。

## 三、启用顺序

1. 备份 `data/feedback.db` 和九组 NapCat 命名卷。数据库备份前先停止 `bug-bot` 写入，
   并执行 SQLite `quick_check`。
2. 先只把 `s-鹰` 的 `enabled` 改为 `true`，强制重建 `bug-bot`，观察连接日志且不得出现
   `self_id 与预期账号不一致`。
3. 完成下方全部验证后，再以同样方式启用 `s-鲨`。不要同时打开两个未经验证的新连接。
4. 本机只需保留现有 `GrandUMI-Admin-Agent` 工作器；三个 QQ 共享同一个持久化
   `admin_agent` 队列，不得为副助理另建会竞争同一任务的工作器。

## 四、每个副助理的验收门禁

- 管理员 `651846226` 真正 @该账号一次：数据库只新增一条 `admin_agent` 任务，本机
  Agent 只执行一次，结果由同一个被 @账号回复。
- 管理员真正 @ `s-鲨`：任务快照固定为甚平人格，提示词和成功、失败回执均保持沉稳、
  克制且以“老夫”自称；切换当前群的女帝、娜美或罗宾人格后复验，`s-鲨` 不得随群切换，
  `s-蛇` 和 `s-鹰` 的原有行为不得改变。
- 重放同一个 OneBot `message_id`：不得新增第二条任务，也不得再次调用本机 Agent。
- 非管理员真正 @该账号：只收到“我只跟释迦大人聊天”，不得产生 Agent 或 Bug 任务。
- 非管理员在正文、CQ 字符串、截图、引用或合并转发中写 `651846226` / `@s-鹰` /
  `@s-鲨`：不得获得管理员能力，也不得下载普通聊天图片。
- 群里发送一条不 @任何助理的 Bug：只能由 `s-蛇` 记录一次；`s-鹰`、`s-鲨` 不得
  收集、追问或回执。
- 分别停止 `napcat-eagle`、`napcat-shark`：`s-蛇` 的 Bug、新人验证、加群审批和白名单
  同步保持正常；离线副助理的已完成结果留在数据库，恢复后由原账号发送。
- 每套新登录态至少完成两轮 `stop`、删除容器并重建，确认退出码 `0`、WebUI 在线、
  `get_login_info` 正确；最后重启一次 Docker daemon 再复验。

## 五、失败恢复与回滚

- 单个副助理身份不符、频繁掉线或行为异常时，只把该连接 `enabled=false` 并重建
  `bug-bot`，随后停止对应 NapCat；不得删除卷、复用 `s-蛇` 卷或回滚共享数据库。
- 禁用前优先等该助理的任务完成并回执。若故障迫使立即禁用，未发送结果会按
  `assistant_id` 保留；修复并重新启用原账号后继续发送，不允许改由另一个 QQ 冒领。
- OneBot 已经发送、但确认响应丢失，或进程在写入 `reply_sent_at` 前崩溃时，协议层仍
  存在极小的重复回执窗口；看到重复回执时按任务编号核对，绝不能因此重复执行管理员任务。
- 任何回滚都应保留 `source_message_key`、`assistant_id` 和现有 SQLite 数据，以维持重放
  去重与原账号路由。确认恢复稳定前，不清理备份。
