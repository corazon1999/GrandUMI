# 效果确认弹窗恢复与手机布局修正

- 日期：2026-09-03
- 分类：修复
- 影响范围：效果确认与选择弹窗、提交等待、断线重连、旧快照兼容及手机竖屏旋转牌桌
- 状态：已完成

## 玩家可见说明

- 点击效果确认后，弹窗会保持显示并明确提示正在等待服务器确认；普通快照、重复下发或断线重连恢复同一操作时，不会再清空当前选择或让弹窗提前消失。
- 等待超过 3 秒时只会重新开放幂等重试，弹窗仍保留；提交等待期间确认、取消和收起入口统一锁定。
- 手机竖屏自动旋转后的确认框会完整留在牌桌可视区，并避开聊天、观战、设置和“更多”等常驻控件；最窄验证尺寸下关键触控区仍不小于 44px。

## 技术说明

- 服务端快照为待处理提示下发操作身份；客户端优先以 `operationId` 维持本地选择、收起态和提交锁，缺少该字段的旧服务端与旧回放确定性回退到 `promptId`。
- 仅发送成功后进入提交等待，不再因本地提交隐藏面板；3 秒计时只解除锁定，不修改权威提示。按钮状态、等待文案和 `aria-busy` 与同一操作身份绑定。
- 旋转牌桌改用容器宽高和映射后的安全区变量；展开态与收起态均为底部控制坞预留 4.5rem。旋转态关键操作使用 64 设计像素，保证 344×582 缩放后仍达到约 44.13 CSS 像素。

## 验证结果

- 前端弹窗与远端演出状态受影响定向 21 项通过；同步远端最新提交后统一门禁中前端完整测试 524 项通过、0 项失败、5 项资源型检查按仓库门禁约定跳过，Next.js 生产构建与 TypeScript 检查通过。
- in-app Browser 实测 344×582、390×844、360×780 三档均自动旋转为 844×390 牌桌：弹窗无越界、与常驻控件零重叠，关键按钮最小边长分别约 44.13px、64px、59.08px。
- 344×582 下模拟提交后 150ms 收到同一操作的重连快照，弹窗持续可见且三个入口均锁定；3 秒后仅解锁重试。浏览器控制台无错误。
