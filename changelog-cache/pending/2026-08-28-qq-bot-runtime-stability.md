# QQ 助理登录与停止稳定性修复

- 日期：2026-08-28
- 分类：修复
- 影响范围：QQ 群助理、NapCat 登录恢复、机器人容器停止
- 状态：已完成

## 玩家可见说明

- 修复 QQ 助理在服务器重建或 Docker 重启后无法自动恢复在线的问题，群内助理现在可以稳定重新连接。
- 优化机器人停止流程，维护重启时会先完成连接和本地数据清理，降低反馈记录异常的风险。

## 技术说明

- NapCat 固定使用经过隔离卷验证的官方 `v4.15.19` amd64 内容摘要，并固定容器主机名与 MAC，避免重建后设备身份漂移；较新登录栈仍保留独立快照和私密密码摘要作为后续受控升级材料。
- 为旧版 WebUI 原子迁移最小兼容配置，保留原 token、回环端口发布和时间戳备份；QQ 登录卷与 WebUI、OneBot 配置保持独立。
- 新增 NapCat PID 1 信号包装器，将停止信号转发到 QQ 整个进程组，并在有界等待后才执行兜底清理。
- 机器人主循环新增 SIGTERM/SIGINT 停止事件，能够中断重连等待和 WebSocket 消费，并收束事件、通知、验证和白名单后台任务。
- 服务器只恢复权威目标群的回复、聊天助理、管理员助理和图片理解；GitHub Issue、自动修复、入群审批、新人验证与白名单同步继续保持关闭。

## 验证结果

- 在完整克隆的 NapCat 三个命名卷上完成静态版本比较、WebUI 与 OneBot 双门，以及两轮停止、删除容器和重建；随后在真实卷前向同步后再次完成两轮同等演练，所有停止退出码均为 `0`，设备身份哈希保持不变。
- Docker daemon 重启后 NapCat 自动恢复，WebUI 在线、OneBot 账号身份与状态正确；正式与测试游戏 systemd 服务和 Nginx 在重启前后均保持运行。
- 新机器人镜像在隔离配置下完成真实 SIGTERM 演练，1 秒内退出且退出码为 `0`；`feedback.db` 的 SQLite `quick_check` 为 `ok`，停止后无 WAL/SHM 残留。
- 本地 QQ 机器人完整自动化测试共 147 项通过；上线后容器无重启、断线、通知或 Traceback 错误，历史待发送队列为空，健康检查未主动发送群消息。
