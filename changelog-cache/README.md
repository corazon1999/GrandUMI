# 更新日志缓存区

这里保存已经完成、但尚未随正式版本发布的 Bug 修复和功能修复记录。

## 目录说明

- `pending/`：待发布记录，一项修复一个 Markdown 文件。
- `published/`：已发布记录，按版本号建立子目录归档。
- `TEMPLATE.md`：新建记录时使用的模板。

## 记录要求

修复实现完成并通过相应验证后，立即复制 `TEMPLATE.md` 到 `pending/` 并填写。文件名使用 `YYYY-MM-DD-简短英文标识.md`，例如：

```text
2026-08-07-life-trigger-completion.md
```

“玩家可见说明”会进入正式更新日志，应使用玩家能理解的语言描述实际变化；内部类名、文件路径、测试数量等内容写在“技术说明”和“验证结果”中。

## 发布检查清单

1. 读取 `pending/` 下的全部修复记录，确认没有遗漏或重复。
2. 按“新增 / 修复 / 优化”分类整理玩家可见说明。
3. 在 `opcgpro-web/src/data/changelog.ts` 的 `CHANGELOG` 数组首部新增版本条目，并设置唯一 `id`、版本号、发布日期和标题。
4. 检查新条目是 `CHANGELOG[0]`，确保 `LATEST_CHANGELOG` 会指向本次版本。
5. 运行与改动对应的测试，并检查更新日志页面能正常读取新条目。
6. 将本次已汇总的记录移动到 `published/<版本号>/`；不得删除原始记录。
7. 确认 `pending/` 中没有本次应发布的记录后，再部署测试服并批准正式发布。

如果某项改动不面向玩家，也仍需留下缓存记录；发布时可将其转写为简洁的稳定性或体验优化说明，避免暴露无意义的内部细节。
