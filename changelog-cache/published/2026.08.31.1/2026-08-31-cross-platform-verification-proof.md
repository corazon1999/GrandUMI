# 跨平台验证证明行尾一致性修复

- 日期：2026-08-31
- 分类：修复
- 影响范围：Windows 发布入口、Linux 发布服务器验证门禁
- 状态：已完成

## 玩家可见说明

- 修复在 Windows 完成全部验证后，Linux 发布服务器可能因脚本行尾格式不同而误判验证策略已变化、从而中止发布的问题；失败后重试会从最后成功版本完整补齐更新，验证证明仍会严格绑定待部署版本。

## 技术说明

- 验证策略摘要不再读取检出目录的原始字节，而是校验提交与 tree 的对应关系后，从声明的目标 Git tree 逐个读取策略文件 blob。
- 摘要继续覆盖策略文件路径、规范 blob 字节长度与完整内容；没有采用行尾归一化，因此目标 tree 中任何真实内容变化仍会导致摘要变化。
- 创建与校验两端均使用同一目标 tree，避免 Windows CRLF 与 Linux LF 工作区表现不同造成误拒绝，同时保持提交、tree、证明文件传输摘要和证明载荷摘要的原有绑定。
- 测试服增量部署改用原子写入的 `test-deployed` 成功状态作为权威基线，不再把可能已被失败流程前移的仓库 HEAD 当作运行版本；基线缺失、格式非法、对象不可用、不是目标祖先或无法比较时会保守执行前后端全量部署并重新安装锁定依赖。
- 测试服部署增加进程级互斥，避免并发请求竞争仓库 checkout、构建目录、服务切换和成功状态写入。

## 验证结果

- `node --test tools/verification-proof.test.mjs tools/deploy-verification-gate.test.mjs`：6 项全部通过。
- 跨行尾回归在独立临时 Git 仓库中以 CRLF 工作区生成证明、再以 LF 工作区校验，同一目标 tree 的证明校验通过。
- 失败恢复回归模拟“仓库 HEAD 已前移、成功部署状态仍停留在旧版本”，确认重试会覆盖旧成功版本到新目标之间尚未部署的前后端变化。
- `git diff --check`：通过。
