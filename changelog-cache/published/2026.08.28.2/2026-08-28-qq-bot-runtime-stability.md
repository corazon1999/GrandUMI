# QQ 助理登录、停止与白名单同步稳定性修复

- 日期：2026-08-28
- 分类：修复
- 影响范围：QQ 群助理、NapCat 登录恢复、机器人容器停止、整点 QQ 白名单同步
- 状态：已完成

## 玩家可见说明

- 修复 QQ 助理在服务器重建或 Docker 重启后无法自动恢复在线的问题，群内助理现在可以稳定重新连接。
- 优化机器人停止流程，维护重启时会先完成连接和本地数据清理，降低反馈记录异常的风险。
- 恢复目标群成员到游戏 QQ 白名单的每小时整点自动更新；失败会保留上一版名单并在管理员面板留下明确记录。

## 技术说明

- NapCat 固定使用经过隔离卷验证的官方 `v4.15.19` amd64 内容摘要，并固定容器主机名与 MAC，避免重建后设备身份漂移；较新登录栈仍保留独立快照和私密密码摘要作为后续受控升级材料。
- 为旧版 WebUI 原子迁移最小兼容配置，保留原 token、回环端口发布和时间戳备份；QQ 登录卷与 WebUI、OneBot 配置保持独立。
- 新增 NapCat PID 1 信号包装器，将停止信号转发到 QQ 整个进程组，并在有界等待后才执行兜底清理。
- 机器人主循环新增 SIGTERM/SIGINT 停止事件，能够中断重连等待和 WebSocket 消费，并收束事件、通知、验证和白名单后台任务。
- 服务器只恢复权威目标群的回复、聊天助理、管理员助理、图片理解和白名单同步；GitHub Issue、自动修复、入群审批与新人验证继续保持关闭。
- 白名单同步权限门从同一份未提交随机密钥生成，测试后端实际加载 `root:root 0600` 环境文件；正式后端在正式维护前不重启、不提前启用。
- Bot 容器把测试域名和唯一正式域名固定直连到授权服务器，仍保留 HTTPS SNI/Host、Nginx 固定来源、代理标记和 Bearer 四层边界，避免 CDN 回源地址破坏来源 ACL。
