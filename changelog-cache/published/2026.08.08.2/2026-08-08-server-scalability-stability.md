# 服务端延迟、容量与稳定性优化

- 日期：2026-08-08
- 分类：优化
- 影响范围：WebSocket 网关、匹配与房间、状态同步、玩家数据、日志持久化、排行榜、监控与发布流程
- 状态：已完成

## 玩家可见说明

- 高峰期大量玩家同时登录、匹配和对局时，服务器排队与卡顿显著降低。
- 网络较慢的玩家不再导致发送队列无限增长；关键对局消息会受到优先保护。
- 在线玩家列表和大厅广播减少重复请求，降低所有玩家同时刷新造成的延迟尖峰。
- 服务端过载时会停止接收新连接或新房间，优先保证已经开始的对局稳定完成。

## 技术说明

- WebSocket 迁移到 Kestrel，并增加连接/房间准入、请求大小限制、连接级令牌桶、有界优先级发送队列、状态与大厅通知合并。
- 状态同步支持客户端协商的增量快照；匹配取消改为 O(1) 墓碑跳过；玩家列表分页并移除前端固定轮询。
- 录像、训练日志与恢复日志改为有界单写批处理；文件打开和批量房间清理改为异步有序收尾，避免线程池饥饿。
- 重复登录时间合并批量落库，排行榜增加短时缓存，持久化目录支持统一外置数据根目录。
- 新增 `/live`、`/ready`、`/version`、`/metrics`，以及版本化发布、健康检查和失败回滚脚本。
- 增加本地房间目录抽象，为后续 Redis/数据库房间路由和多节点粘性调度保留边界。

## 验证结果

- 服务端自动化测试：578/578 通过。
- 前端：Next.js 16.2.6 生产构建通过。
- 纯连接压测：1000/1000 WebSocket 成功，4000 次心跳 0 丢包、0 异常断线，P95 52.39ms。
- 完整对局压测：1000 名玩家、500 个房间全部完成登录、匹配、先后手选择和调度手牌；0 异常断线、0 消息丢弃、0 持久化丢弃，稳态工作集约 283MB。
- 500 个房间同时结束后房间数归零，`/ready` 继续返回 200，实测约 92ms。
- OP15 网络匹配端到端流程通过；版本、存活、就绪和 Prometheus 指标端点均通过独立发布实例验证。
