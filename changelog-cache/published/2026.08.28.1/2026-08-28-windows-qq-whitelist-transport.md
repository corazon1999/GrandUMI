# 修复 Windows 白名单导出脚本传输字节偏差

- 日期：2026-08-28
- 分类：修复
- 影响范围：Windows 一键实时 QQ 白名单导出、SSH 远端采样脚本传输
- 状态：已完成

## 玩家可见说明

- 修复部分 Windows PowerShell 环境下一键导出可能因脚本传输编码差异而失败的问题；远端采样前现在会校验脚本原始字节，异常时直接停止且不会生成伪成功文件。

## 技术说明

- 本地脚本先把远端采样器按 UTF-8 原始字节编码为 Base64，并携带源文件 SHA-256；远端只从标准输入解码、逐字节复核摘要后执行，不创建远端临时文件。
- 启动 SSH 子进程前临时将 Windows PowerShell 5.1 的控制台输入编码切换为无 BOM UTF-8，进程启动后立即恢复，再通过标准输入原始字节流写入，避免 `Process.Start()` 创建的写入器预先注入 BOM。
- 双击入口使用非交互 `-NoPause` 调用，并保留失败暂停行为；新增隐藏传输自检用于验证 ASCII 信封、源长度、解码长度与三方摘要一致。

## 验证结果

- Windows PowerShell 5.1 真实传输自检通过：源文件、本地往返与子进程解码后的长度和 SHA-256 完全一致，输入信封保持 ASCII。
- `qq-bug-bot.tests.test_live_qq_whitelist_export` 全部通过，覆盖 Base64 字节传输、远端源摘要校验、原始标准输入流、无远端临时文件和双击入口参数。
- QQ 机器人完整测试 143/143 通过；`git diff --check` 无空白错误。
