# 服务端容量测试隔离宿主内存压力

- 日期：2026-09-03
- 分类：修复
- 影响范围：服务端自动化测试基础设施、服务容量保护回归验证
- 状态：已完成

## 玩家可见说明

- 玩家行为没有变化；正式运行的服务仍会依据真实宿主内存压力拒绝新连接或新房间。
- 服务端自动化测试不再因同机运行 Unity 等高内存应用而随机出现 `memory_pressure` 失败。

## 技术说明

- `ServerCapacity` 的生产默认来源仍为 `GC.GetGCMemoryInfo()`，没有增加可由环境变量或公开 API 关闭容量保护的入口。
- 测试程序集通过模块初始化器一次性安装内部合成内存快照；安装使用原子的一次性门禁，不允许测试运行中替换或复位，避免并行测试相互污染。
- 提供生产来源与测试覆盖之间的内部选择边界，并补充默认生产来源、测试覆盖优先级及一次性安装约束测试。

## 验证结果

- `GrandUmiTestTempPolicyTests` 与会创建房间的 `ChatDecorationCinematicTests` 共 9 项全部通过。
- 服务端 Release 完整测试 2088 项通过、2 项按平台条件跳过、0 项失败；此前受影响的创建房间测试均未再出现 `memory_pressure`。
- 修复前同一提交的完整服务端验证曾有 33 个创建房间测试随宿主 GC 内存压力报 `memory_pressure`；同一测试的后续单类运行会随宿主压力回落而通过，确认失败依赖实时宿主状态而非业务输入。
