# OP16-017「小奥兹Jr.」自身条件静态减力效果补实现

日期：2026-06-15

## 问题

用户反馈：OP16-017 在满足条件的场合，自己的力量没有减少。

卡面：
> 我方场上**不存在**费用为8或更高且特征中包含〈白胡子海盗团〉的角色的场合，此角色力量-4000。
> 【阻挡者】

根因：该卡的持续效果**从未实现**——DSL 定义文件 `Effects/Definitions/OP16.json` 无此条目，
`Effects/Scripted/` 也无对应脚本（全仓仅在对局日志中出现过被打出记录）。因此力量恒为印刷值 8000，
"满足条件（场上没有8费白胡子角色）时应 -4000"从未生效。

## 修复

新建 `服务端WebSocket/Effects/Scripted/OP16_017_LittleOzJr.cs`（IScriptedEffect，反射自动注册，无需改 JSON）。

实现：登场（OnEnterField）时注册一条 `ContinuousEffect`：
- `PowerDelta = -4000`，仅作用自身（Predicate 限定 `c.Id == selfId`）。
- 激活条件 Predicate：我方场上不存在「`CurrentCostOf >= 8` 且 `HasKeyword("白胡子海盗团")`」的角色时为 true。
- 动态实时判断：满足条件的角色登场/离场会自动让减力失效/重新生效。
- 来源卡离场由 TurnEngine 按 SourceCardId 自动清理。

复用既有机制（未改框架代码）：
- `ContinuousEffect` + `GameState.CurrentPowerOf`/`ContinuousPowerBonus`（`Game/GameState.cs:78,90`）。
- 范例参照 `Effects/Scripted/OP16_003_Newgate.cs`（同样登场注册持续力量修正）。

## 关键正确性点

- 全链路生效：战斗判定 `BattleEngine.cs:101/108/116` 与快照显示 `StateSnapshotBuilder.cs:95/114` 均走
  `CurrentPowerOf` → `ContinuousPowerBonus`，故减力在打点和前端均反映。
- 特征精确匹配：`CardInfo.HasKeyword` 为精确 token 比较（`Cards/CardInfo.cs:45`），
  OP16-017 自身的「白胡子海盗团旗下」不会被误判为「白胡子海盗团」。
- 费用判定走 `GameState.CurrentCostOf`，兼容持续费用光环。

## 验证

`dotnet build -p:OutputPath=bin\verify\`（输出到临时目录以避开运行中服务器对 exe 的文件锁）
→ 已成功生成，0 警告 0 错误。临时目录已清理。
