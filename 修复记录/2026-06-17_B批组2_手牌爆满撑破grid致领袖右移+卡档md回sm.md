## 现象与用户澄清

- #36 用户原描述"随回合右移"，实测澄清为**随手牌张数增多右移**（GM 每回合加 1 张手牌，正好与回合数同步，故误判）。截图中我方领袖卡已被挤到右下角 DECK 下方。
- #37 手牌爆满时整条手牌从屏幕中部一直平铺到最右，盖住右下 STAGE/TRASH，`overflow-x-auto` 未生效（是撑破溢出，不是滚动）。

## 根因（#36 与 #37 同源）

`GameBoard.tsx` 的 `PlayerMat` 用 `grid grid-rows-[1fr_auto_1fr]`（单列）。**grid 单列宽度 = 所有行中最宽那行的 min-content**。手牌行的 grid item 没有 `min-w-0`（CSS grid item 默认 `min-width:auto`，不会收缩），手牌越多该行 min-content 越宽 → 把整个 grid 单列撑宽 → 同一 grid 的「咚+领袖」行（第2段 `grid-cols-[0.9fr_1.1fr]`）也跟着变宽，领袖在 `justify-self-center` 的右半区居中 → 整体被推到最右（DECK 下方）。这解释了"领袖右移"与"手牌外溢"是同一个原因。

雪上加霜：`CardSizeOverride.Provider` 被从 `sm` 改成了 **`md`**（记忆 [[game-page-responsive]] 明确 720 高画布应用 sm，md 会纵向溢出重叠），卡牌大一圈使手牌行 min-content 更宽，放大了溢出与拥挤（#17）。

## 修复（纯前端，一次解决 #36 + #37 + #17）

`opcgpro-web/src/components/game/GameBoard.tsx`：
1. 卡牌档位改回 `sm`：`<CardSizeOverride.Provider value="sm">`（第245行，曾被误改为 md）。
2. 手牌行 grid item 补 `min-w-0`：`relative min-h-0 pl-24 md:pl-28` → 加 `min-w-0`（对手第72行 + 我方第97行，replace_all）。
3. 角色行 grid item 补 `min-w-0`：`relative flex min-h-0 items-stretch gap-4 …` → 加 `min-w-0`（两处，防角色多时同样撑破）。
4. 第2段「咚+领袖」行补 `min-w-0`。

`opcgpro-web/src/components/game/HandArea.tsx`：
5. 手牌根容器补 `w-full min-w-0`（第66行），让 `overflow-x-auto` 真正变成横向滚动而非撑破。

核心知识点：**grid/flex 子项要让内部 `overflow` 生效、不被内容撑破，必须显式 `min-w-0` 覆盖默认 `min-width:auto`**。
