# OP16-049 — 【启动主要】漏写「横置自身」成本

## 现象
- 发动波特夹斯·D·艾斯【启动主要】，抽了 1 张，但**没有横置自己**（成本没付）。

## 卡面
- 【启动主要】**可以将此角色转为休息状态**：抽取1张卡牌。
- 冒号前「将此角色转为休息状态」=成本；冒号后「抽1」=收益。

## 根因
- DSL（`Definitions/OP16.json`）的 `activated` 节只写了 `Draw 1`，**漏写 `cost`（横置自身）**；还误加了 `oncePerTurn`。
- DSL 的 `activated.cost` 其实**原生支持 `restSelf`**（`DslInterpreter.PayActivationCost`：横置自身，已横置则返回 false 不发动），执行顺序为「先 PayActivationCost → 再 RunSteps(then)」，本就满足「成本先付」。原定义没用它。

## 修复（OP16.json 一处）
```json
"activated": {
  "cost": { "restSelf": true },
  "then": [ { "op": "Draw", "n": 1 } ]
}
```
1. **加 `cost.restSelf`** → 先横置自己再抽（顺序正确）。
2. **去掉 `oncePerTurn`** → 卡面无【每回合1次】；横置自己后自身已横置，`restSelf` 自然使一回合最多发动一次。保留 oncePerTurn 反而错：若有卡让其重新活跃，本应能再发动，oncePerTurn 会错误禁止。

## 波及卡牌
- 同属「冒号前=成本」规则（见记忆 `cost-before-colon-execution-order`）。
- DSL 启动效果若成本是「横置自身」，直接用 `activated.cost.restSelf` 即可，无需转脚本（区别于 OP16-047/043 因收益复杂或 triggers 无 cost 通道才转脚本）。
- 提醒：DSL 中用 `oncePerTurn` 模拟「横置自身天然限一次」是错误手法，应改用 `cost.restSelf`。可后续抽查其它 activated 是否有同类「该用 restSelf 却用 oncePerTurn / 漏成本」。

## 预防
- 冒号前成本必付：DSL activated 用 `cost`（restSelf/donReturn/handDiscard/selfToTrash/restActiveDon 等），不要把成本省略或用 oncePerTurn 替代。

## 验证
- OP16.json `ConvertFrom-Json`：语法 OK。
- 后端 `dotnet build --nologo`：0 错误 0 警告。
