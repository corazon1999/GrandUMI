# OP16-048 — 巴奇：囚犯按卡名匹配 + 补「对方攻击时」阻挡者效果

## 现象
1. 【登场时】只抽了 1 张，**不提示登场「因佩尔地狱的囚犯」**。
2. 【每回合1次】当对方进行攻击时，**无任何效果选择提示**（整段没生效）。

## 卡面
- 【登场时】我方领袖拥有《因佩尔地狱》特征的场合，抽取1张卡牌，将我方手牌中最多1张"因佩尔地狱的囚犯"登场。
- 【每回合1次】当对方进行攻击时可以发动。本回合中，我方最多1张"因佩尔地狱的囚犯"获得【阻挡者】效果。

注意区分引号语义：《因佩尔地狱》= **特征/关键词**；"因佩尔地狱的囚犯" = **卡名**（OP16-042 卡名即此）。

## 根因
1. **登场段 filter 误用**：原 DSL 写 `"keywordContains": "因佩尔地狱的囚犯"`，按「特征包含此串」去匹配手牌——但囚犯是**卡名**不是特征，没有任何卡的特征含这串字 → `PlayCharFromHand` 候选数 0 → 直接 `break` 不弹窗（`DslInterpreter.cs:1267`）。
2. **对方攻击段未实现**：`triggers` 里原本只有 `OnEnterField` 一段，第二段效果从未写（`_matcher` 自标「未做」）。

## 修复（OP16.json 一处，OP16-048）
1. **登场段** `keywordContains` → `nameEquals`（与同系列 OP16-031「登场囚犯」一致）。
2. **新增第二段触发**：
```json
{
  "on": "OnOppAttackDeclare",
  "oncePerTurn": true,
  "then": [
    { "op": "Choose", "prompt": "OwnCharacter",
      "filter": { "nameEquals": "因佩尔地狱的囚犯" },
      "max": 1, "min": 0, "as": "$blk",
      "text": "选择我方最多1张「因佩尔地狱的囚犯」本回合获得【阻挡者】" },
    { "op": "GiveKeyword", "target": "$blk", "keyword": "阻挡者" }
  ]
}
```

各原语链路（已核源码）：
- `OnOppAttackDeclare`（对方攻击时）+ trigger 级 `oncePerTurn` 已支持（`EffectTrigger.cs:10`、`DslInterpreter.cs:104/188`）。
- `Choose` prompt `OwnCharacter` 取我方场上角色，`filter.nameEquals` 复用卡牌过滤（`1530`/`1427`）；`min:0` 让"可以发动"可放弃。
- `GiveKeyword` 默认 `ThisTurn` → 写 `CardInstance.GainedKeywords`（`AtomicOps.cs:263`）→ `ActionValidator.HasKeyword:108` 读它 → 战斗阻挡判定 `GameEngine.cs:539` 生效；`TurnEngine` 回合末自动清理；快照下发 `gainedKeywords` 客户端显示阻挡者徽标。
- `$blk` 为 null（选 0 张）时 `ResolveTarget` 返回 null，`GiveKeyword` 有 `if(target is not null)` 兜底，无副作用。

## 波及卡牌
- 全库扫描 `keywordContains.*囚犯`：**误用仅 OP16-048 这 1 例**；其余引用「因佩尔地狱的囚犯」的卡（OP16-031 等）均已用 `nameEquals`，无需改。

## 预防
- 「**名为**X」「**名字**为X」→ 用 `nameEquals`（精确）或 `nameContains`（包含）。
- 「拥有《X》特征」「特征中含X」→ 才用 `keyword`（精确）/`keywordContains`（包含）。
- 写卡效前先分清卡面引号：《》=特征，""=卡名。

## 验证
- OP16.json node 解析：合法；OP16-048 现 2 段触发 `OnEnterField, OnOppAttackDeclare`，两 filter 均 nameEquals，第二段 oncePerTurn=true。
- 后端 `dotnet build`：0 错误 0 警告。
