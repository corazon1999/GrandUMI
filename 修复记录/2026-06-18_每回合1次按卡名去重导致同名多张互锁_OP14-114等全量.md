# 2026-06-18 「每回合1次」按卡名去重导致同名多张互锁（全量修复）

## 现象
场上两张 OP14-114（阿兰），发动其中一张的【启动主要】效果后，另一张的同名效果无法再发动（点了没反应）。

## 根因
`oncePerTurn`（每回合1次）的去重标记按**卡号**记录，而非按**卡实例**。
同名多张共用同一个「本回合已用」key，发动一张即把全部同名卡锁住。

涉及两套机制，问题相同：

1. **DSL 解释器** `服务端WebSocket/Effects/Dsl/DslInterpreter.cs`
   - `CheckOncePerTurn` / `MarkOncePerTurnUsed`：key 原为 `{Info.Number}-Activated`
   - `CheckTriggerOncePerTurn` / `MarkTriggerOncePerTurnUsed`：key 原为 `{Info.Number}-Trigger-{触发名}`
   - 覆盖所有用 JSON `oncePerTurn` 定义的卡（含 OP14-114）。

2. **C# 脚本卡** `服务端WebSocket/Effects/Scripted/*.cs`
   - 约 170 个脚本用玩家级 `me.TurnOnceUsed`，key 形如
     `self.Info.Number + "-act"` / `ctx.Source.Info.Number + "-xxx"` / `CardNumber + "-xxx"` / 硬编码卡号字面量 / `const string key="..."`。
   - 角色卡可放多张 → 真 bug；领袖/舞台单实例 → 原本不出错，但一并规范化也无害。

> 注：实例级 `OncePerTurnUsedKeys`（CardInstance 自带，命名为 `PendingKey` 等大写）本就按实例，无需改；脚本里已带 `:{self.Id}`/`:{ctx.Source.Id}` 的也已是按实例，跳过。

## 修复
统一把 key 从「卡号」改为「卡实例 Id」（`CardInstance.Id`，每实例唯一 Guid）。

- DSL：`{Info.Number}` → `{ctx.Source.Id}`（Activated 与 Trigger 两套共 4 处）。
- 脚本：在原 key 末尾追加 ` + ":" + self.Id`（或 `ctx.Source.Id`）；`const string` 改 `var`。
  用受控正则批量改写：仅匹配方法内局部变量 `key`/`dkey`（小写，天然避开大写 `PendingKey` 字段），
  右值引用卡身份且未含 `.Id` 才改。共 170 文件 / 173 行。

## 关键坑（已规避）
`GameEngine.cs:392` 有跨文件**字面量**读取：`lucciPlayer.TurnOnceUsed.Contains("OP15-002-MainOncePerTurn")`，
依赖 `OP15_002_Lucci.cs` 写入的字面量 key。若给该脚本 key 加实例 Id 会导致字面量失配、路西联动抽牌失效。
OP15-002 是领袖（单实例）本就不需要按实例 → **已将 `OP15_002_Lucci.cs` 排除**，保持字面量不变。
全仓库经核查，唯一这一处字面量跨文件引用。

## 验证
- `dotnet build`：0 错误 0 警告。
- 抽查 OP14-105、EB04-044（双 key）改动正确；OP15-002 未改；DslInterpreter 已改。

## 影响
`TurnOnceUsed` 每回合清空，改 key 格式无持久化问题。改后同名多张角色卡的【每回合1次】各自独立计数（符合 OPTCG 规则）。需重启后端生效。
