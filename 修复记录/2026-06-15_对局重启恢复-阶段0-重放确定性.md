# 对局重启恢复 · 阶段0：重放重建确定性验证

日期：2026-06-15

## 背景与目标

需求：服务器重启后，未超时（自最后一次操作起 30 分钟内）的对局，玩家刷新页面应能回到对局。

技术结论：整局状态无法序列化（永续效果含委托、效果解析含挂起的 async 续延），唯一可行路线是
**重放重建**——用原始 `RngSeed` + 牌组 + 有序动作磁带重新执行引擎，让状态自然长回来。

阶段0 目标：离线证明"同 seed + 同动作磁带 → 逐字节相同的对局状态"，作为整功能成立的前提。
本阶段**只做验证、不接入持久化/启动恢复/客户端**。

## 新增机制（生产代码，向后兼容）

1. `Game/DeterministicId.cs`（新）：`AsyncLocal<Func<Guid>?>` 环境化 ID 工厂 + 由 int seed 派生的
   确定性 GUID 序列。卡实例 ID 不再随机，重放时动作 data 里引用的 GUID 原样可用。
   - `Game/CardInstance.cs` / `Game/DonCard.cs`：`Id = Guid.NewGuid()` → `DeterministicId.Next()`。
   - `Game/GameEngine.cs`：构造函数（建任何卡之前）与 `HandleAction` 入口设置 `DeterministicId.Current`。
2. `Game/GameEngine.cs`：加"空闲屏障"——把各 fire-and-forget 效果链 `_ = XxxAsync()` 包一层 `Track()`
   记录最外层任务，新增 `WaitSettledAsync()`：等效果链"解析完 或 挂起在 PendingPrompt"。重放逐动作间 await 它。
3. `Game/MatchReplay.cs`（新）：重放驱动。构造静默引擎（不挂任何回调→广播/日志/录像天然 no-op），
   按序喂动作、动作间 await 空闲，产出重建的 state。
4. `服务端WebSocket.Tests/ReplayEquivalenceTests.cs`（新）：
   - 同 seed 同磁带 → 私有快照逐字节相等（含所有 GUID）；
   - 不同 seed → 快照不同（证明 RNG 生效）；
   - 确定性 ID 跨重建稳定；
   - **autopilot 全程对局（打牌+效果+prompt 响应+结束回合）重放后逐字节一致**。

## 阶段0 期间发现并修复的潜伏 bug（均同时影响生产）

这些 bug 在并发对局 / 重放下会导致状态错乱，是确定性与并发安全的真问题，非仅测试问题：

1. **`Effects/AtomicOps.cs` 共享时间种子 `Random`**（最严重）：`Shuffle` 用 `private static readonly Random _rng = new()`，
   5 处效果洗牌全部不受 `RngSeed` 控制 → 重放必发散、并发房间互相干扰。
   修复：洗牌统一走 `GameState.Rng`（由 `RngSeed` 惰性派生）；`Shuffle<T>` 改签名为 `Shuffle(GameState s, List<T>)`；
   `GameEngine` 自身洗牌也并入 `State.Rng`（删除独立 `_rng`）；5 处调用点改传 `ctx.State`。
2. **`Effects/EffectRuntime.cs` `[ThreadStatic]` 的 `_ambient/_depth/_draining`**：效果解析大量 async，续延在
   线程池任意线程恢复，跨 await 后会读到该线程上别的引擎留下的值（watcher 入错队列 / 并发污染）。
   修复：改为 `AsyncLocal`（随 async 流动；被调用方改动不回流，恰好实现"最外层判定"）。
3. **`Effects/EffectRuntime.cs::ScriptedEffectRegistry.ScanAll`**：`_scanned=true` 在反射填充字典**之前**置位，
   并发首次 `TryGet` 时另一线程见 `_scanned==true` 跳过扫描却读到空字典 → 脚本卡效果被漏判
   （表现为领袖永续被动偶发不注册、`continuousEffects` 为空）。修复：加锁 + `_scanned` 置位移到填充之后 + `volatile`。
4. **`Cards/CardDatabase.LoadFrom` / `Effects/Dsl/DslInterpreter.LoadDirectory` 非幂等非线程安全**：并发重复加载
   直接并发写静态字典 → 损坏 → `Get` 抛 NRE。修复：两者均加 幂等 + 锁（生产只调一次，行为不变）。

另修复 `服务端WebSocket.Tests/TestScene.cs` 的坏合并（重复声明 + 缺 `required RngSeed`，原本导致测试工程编译不过）。

## 验证

- 全量测试 151 全过；连跑 6 次稳定无 flaky（修 bug 前 autopilot 在并行下偶发失败）。
- autopilot 测试断言对局推进多回合且确实触发过 prompt，覆盖到带 prompt 的重放路径。
