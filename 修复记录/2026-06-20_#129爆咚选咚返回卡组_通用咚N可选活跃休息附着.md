# 2026-06-20 #129「爆咚无法选择」——通用「咚!!-N」放回改为弹窗手选（活跃/休息/附着均可选）

## 反馈与根因
反馈 #129「爆咚无法选择」= OP16-060 战国（放回大量咚召唤大将的爆发流，今日对局日志出现 4 次）。

排查发现这是**通用「咚!!-N」机制**的缺陷，不止战国：
- 旧 `AtomicOps.ReturnDonToDeck(p, n)`：自动放回，只取**活跃+休息**咚，**排除附着在角色/领袖身上的咚**。
- 各「咚!!-N」卡的发动门槛大多判 `me.ActiveDonCount < n`（只数活跃咚）。
- 结果：咚一旦被横置或赋予给角色/领袖，即使费用区总数够，也凑不齐"活跃"那一档 → 卡变灰、发动不了。

按 OPCG 规则，卡面「将指定数量的咚放回」(咚!!-N) 本应能放回**任意状态**的咚（活跃/休息/附着），由玩家自选。这才是 bug。

## 用户决策（方案先行确认）
1. **战国 OP16-060 保持"仅活跃"**——其官方原文是「将我方**8张活跃状态**的咚放回」，遵循卡面，不改。
2. **放回改为弹窗让玩家手动点选**要放回哪几张（含附着咚）。

## 改动

### Phase A — 引擎 + DSL + 客户端
- **引擎** `Effects/AtomicOps.cs` 新增 `PromptReturnDonToDeck(EffectContext ctx, int n) : Task<bool>`：
  - 合格咚 = 费用区全部（活跃+休息+附着，`CostArea.Count` 即合格数）。不足 n 或玩家取消 → 返回 false（调用方据此中止发动，不产生半支付）。
  - **全活跃时自动放回**（彼此等价、无抉择，免无意义弹窗）；**存在休息/附着才弹窗**手选。
  - 选定后逐张：脱离附着 → 入咚卡组；触发 `OnDonReturnedToDeck` watcher。放回附着咚会使角色/领袖失去贴咚加成（power 由 `AttachedDonCount` 派生，自动生效）。
  - 旧同步 `ReturnDonToDeck(p,n)` 保留：供战国（仅活跃自动）与对方强制放回沿用。
- **DSL** `Effects/Dsl/DslInterpreter.cs` 的 `donReturn` 成本改走助手（**一处覆盖 52 个 DSL 效果**）。
- **客户端** `opcgpro-web/src/components/game/PromptOverlay.tsx` 新增 `ReturnOwnDon` 分支：
  服务端用 `extra.donChoices`（每张咚 id/状态/附着目标卡号·名）下发；前端渲染咚 token（活跃竖置/休息横置、附着标"贴：X"），多选恰好 n 张确认。咚牌无卡号、不在 fieldCards，故走独立分支不复用通用卡图反查。

### Phase B — 脚本卡 73 张
通用「咚!!-N」脚本卡全部转换：
- 门槛 `me.ActiveDonCount < n`（或 `CostArea.Count(d=>Active||Rest) < n`）→ `me.CostArea.Count < n`。
- 支付 `AtomicOps.ReturnDonToDeck(me, n)` → `if (!await AtomicOps.PromptReturnDonToDeck(ctx, n)) return;`；用返回值计数的（`int returned/paid=...; if(<1)`）一并改掉。
- 6 张原同步 `Task Resolve` 升为 `async Task`（OP12-061、OP13-064、OP08-074、OP08-119、ST04-001、ST26-005）。

**排除（保持仅活跃，符合卡面）**：`EB02-061 路飞`（2张活跃咚）、`OP16-060 战国`（8张活跃咚）。
**对方强制放回保持自动**：`OP02-085 麦哲伦`、`OP15-059 亚马逊`（`ReturnDonToDeck(opp,n)` 不动）。

> 注：注释里写"活跃"但官方原文为通用咚!!-N 的卡（EB03-034/EB04-031/OP05-119/OP10-071/OP12-069/OP12-075/OP13-069/P-005 等），其"活跃"均指**从咚卡组追加活跃咚**或对方追加，放回成本本身通用——已按官方原文转换。
