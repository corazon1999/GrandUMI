# 2026-06-18 触发型「可选成本」不弹确认（DSL 通用修复）

## 现象
ST30-012（路飞 #53）【登场时】横置1咚：本回合此角色获得【速攻】——登场时没有弹出"是否横置1咚获速攻"的确认框，成本被静默处理。

## 根因
`DslInterpreter.cs` 的 `triggers`（触发）分支对带 `cost` 的效果**一律自动支付、从不弹确认**（直接 `PayActivationCost`）。
但 OPTCG 中「【登场时/攻击时/对方攻击时/KO时/我方回合结束时…】成本：效果」这类触发型成本**都是可选的**（"你可以支付…"）。

这是全 DSL 通病：ST04/05/06/09/10/11/13/18/19/22/24/26/30、OP16、PRB02 等 **40+ 张**触发带成本卡都被静默自动扣成本，ST30-007/012 的「横置1咚获速攻」只是被发现的一例。

## 修复（通用）
改 `triggers` 分支：对带成本的触发效果——
1. **可支付预检**：不能支付则静默跳过，不打扰玩家（新增只读函数 `CanPayActivationCost`，不产生状态变化）。
2. **静默类成本弹确认**：`donReturn / restSelf / selfToTrash / restActiveDon / millTop / lifeToHand / handDiscard(数字)` 这些无独立选择界面的成本，先 `ConfirmOptional`，玩家可放弃（新增 `CostNeedsConfirm` 判定）。
3. **交互类成本不重复确认**：`handDiscard(对象) / revealHand / trashOwnCharacter` 本身用「选0张=放弃」让玩家拒绝，不再额外弹窗，避免双重确认。

确认文案：触发节可选 `costPrompt` 字段自定义，缺省用通用语「是否支付成本以发动此效果？」。
已给 ST30-007（艾斯）、ST30-012（路飞）的速攻触发加 `costPrompt`："横置1咚：本回合此角色获得【速攻】？"

> 注：`costPrompt` 已被解释器读取，非静默忽略键。`activated`/事件/反击 等玩家**主动发动**的成本不受影响（本就由玩家主动选择发动，不需二次确认）。

## 验证
- `dotnet build`：0 错误 0 警告。
- ST30.json `ConvertFrom-Json` 解析通过。

## 影响
所有触发型带成本卡现在会在支付前征求玩家同意（可支付时），符合 OPTCG「可选成本」规则。需重启后端生效。
