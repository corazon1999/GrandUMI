# 2026-06-16 持续效果谓词递归导致栈溢出（OP16-017 触发）

日期：2026-06-16

## 问题
GM 召唤 OP16-017「小奥兹Jr.」后服务端崩溃，堆栈在
`ContinuousPowerBonus → Weaken → CurrentCostOf → ContinuousCostBonus → Weaken → …` 间无限递归，最终栈溢出。

## 根因（框架层）
`GameState.ContinuousPowerBonus` / `ContinuousCostBonus` 在累加前**对每一个持续效果都直接调 `Predicate`**，
未先判断该效果是否真的影响这个维度。

OP16-017 的持续效果只改力量（`PowerDelta=-4000`，`CostDelta=0`），其谓词 `Weaken` 内部要查
"场上是否有 8 费〈白胡子海盗团〉角色" → 调 `CurrentCostOf` → `ContinuousCostBonus`。
而 `ContinuousCostBonus` 又对 OP16-017 这条（费用增量为 0 的）效果求值谓词 → 再次进入 `Weaken` → 再查费用 → 死循环。

对比：其余同类方法（`HasContinuousKeyword`/`IsKoGuarded`/`IsContinuouslyNullified`/`IsTriggerNullified`/`IsResetPrevented`）
都是**先按相关字段短路、再调谓词**，唯独这两个数值累加器漏了该过滤。

## 修复
`Game/GameState.cs` 两处，在调 `Predicate` 前先跳过对应增量为 0 的效果：
- `ContinuousPowerBonus`：`if (eff.PowerDelta == 0) continue;`
- `ContinuousCostBonus`：`if (eff.CostDelta == 0) continue;`

效果：
- OP16-017 效果 `CostDelta=0` → 费用查询不再求值它的谓词 → 递归切断；
  力量查询 `PowerDelta=-4000≠0` → 谓词照常求值 → -4000 正常生效。
- 与其余持续效果方法的"先过滤再调谓词"模式统一；零增量本就不贡献数值，语义无损，且省一次谓词调用。

## 残留说明
若未来出现"费用效果的谓词内查同卡力量"这类交叉依赖，仍可能递归；当前卡池无此情形，
本次按维度短路已覆盖全部现有卡。若将来需要，再引入按卡的重入保护。
