卡号: OP12-001（及波及：OP08-055 / OP12-003 / OP12-004 / OP12-009 / OP12-013 / OP12-015 / OP13-024 / OP14-105 / OP07-090）
日期: 2026-06-15
现象: 以"公开我方手牌中 N 张……"为发动成本的卡，发动时只在发动者自己屏幕弹出选牌框，对手屏幕上既不翻面也无任何提示——对手无从确认发动者确实公开了符合条件的牌，不符合 OPTCG「公开」语义。摩根斯(OP07-090)的"对方公开其手牌"同样对发动者不可见。
根因: 这批"公开手牌"成本由各自 C# 脚本用 ChooseCards(ctx.OwnerIndex, ...) 实现，只把候选牌面通过 prompt 的 extra.choiceCards 下发给发动者本人选择，选完后未调用引擎的公开通道。引擎已有公开通道 GameEngine.BroadcastReveal(ownerIndex, cardNumbers)（即设即清的瞬时浮层，客户端 RevealOverlay 居中展示约 2.5s，双方可见），但仅 DSL 的 revealHand 成本(DslInterpreter.cs:240)与 OP16-003 纽哥特接入了它，其余脚本卡漏接。OP07-090 注释更直接写"引擎无对应公开手牌通道，省略"——属过时认知。
修复: 在每张卡公开成本支付成功（ChooseCards 返回数量达标）之后、效果结算之前，补一句
  ctx.Engine?.BroadcastReveal(ctx.OwnerIndex, 选中id映射回的 Info.Number 列表);
公开≠丢弃，被公开的牌仍留在手牌，不改变其它状态。OP07-090 摩根斯为反向语义（让对方公开手牌给发动者看），在对方丢弃后、抽牌前调 BroadcastReveal(1 - ctx.OwnerIndex, 对方当前全部手牌番号) 并更新其注释。
波及卡牌: 全量排查 Scripted 目录"公开手牌/公开……卡牌"成本类，共修 10 张：
  - 事件类(公开2张事件)：OP12-001 雷利 / OP12-003 克罗卡斯 / OP12-004 光月御殿 / OP12-009 甚平 / OP12-013 小八 / OP12-015 路飞
  - 特征类：OP08-055 凤凰印(2张白胡子) / OP14-105 戈耳工三姐妹(3张亚马逊·百合/九蛇) / OP13-024 哥顿(1张音乐/FILM)
  - 反向公开：OP07-090 摩根斯(公开对方全部手牌)
  已确认无须改：OP16-003 纽哥特、DSL revealHand 通用成本——本就已调 BroadcastReveal。
预防: 凡卡面含"公开"（无论公开手牌作成本、还是让对方公开手牌）都必须走 ctx.Engine?.BroadcastReveal，让双方都能看到牌面；新写"公开"类脚本卡时对照本条自查。注意：BroadcastReveal 只触发瞬时居中浮层，客户端手牌区(HandArea)对敌方一侧恒渲染为牌背，公开不会让手牌在原位翻面——这是设计如此。
