# OP16-048 — 阻挡者误标自身 + effectTags 漏补致对方攻击段不触发

## 现象（用户反馈 2026-06-22）
1. OP16-048 自己不该有阻挡者词条，但场上它能当阻挡者用。
2. 【每回合1次】对方攻击时，仍**没有**"给最多1张'因佩尔地狱的囚犯'赋予阻挡者"的选择提示。

## 卡面（原文已核 卡牌数据_含原文/OP16.json）
- 【登场时】我方领袖拥有《因佩尔地狱》特征的场合，抽取1张卡牌，将我方手牌中最多1张"因佩尔地狱的囚犯"登场。
- 【每回合1次】当对方进行攻击时可以发动。本回合中，我方最多1张"因佩尔地狱的囚犯"获得【阻挡者】效果。

→ **卡自身没有阻挡者**，它是把阻挡者赋予「囚犯」(另一张卡 OP16-042)。

## 根因（两个独立 bug）
### ① 自身误带阻挡者
`卡牌数据/OP16.json` 里 OP16-048 的 `abilities` 被误写成 `["阻挡者"]`——解析器把效果文里"获得【阻挡者】"当成了自身词条。
后端 `ActionValidator.HasKeyword`（`Game/Validation/ActionValidator.cs:107`）：
```csharp
if (Array.IndexOf(c.Info.Abilities, kw) >= 0) return true;  // 静态词条 → 无条件 true
```
于是这张卡真的能当阻挡者宣言、并显示阻挡者徽标。

### ② 对方攻击段不触发
上次修复（`修复记录/OP16-048_囚犯按卡名匹配+补对方攻击阻挡者效果.md`，06-21）给 DSL（`Effects/Definitions/OP16.json`）加了第二段 `OnOppAttackDeclare`，**但没同步给卡数据补 effectTags**。
后端派发触发只认 `Info.EffectTags`：`EffectRuntime.HasEffectForTrigger`（`Effects/EffectRuntime.cs:226`）→ `CollectListeners` 遍历全场时该卡 EffectTags 只有 `["OnEnterField"]` → 对方攻击时根本不把它收进监听者 → DSL 第二段永不执行 → 无提示。
`_add_tags_from_scripts.js` 只扫描 Scripted/*.cs 脚本卡，**管不到 DSL 卡**，所以 DSL 卡加触发段必须手工补 tag。

## 修复（2 份数据文件，各 2 处，OP16-048 条目）
| 文件 | abilities | effectTags |
|---|---|---|
| 卡牌数据/OP16.json（后端权威，CardDatabase 启动加载） | `["阻挡者"]` → `[]` | `["OnEnterField"]` → `["OnEnterField","OnOppAttackDeclare"]` |
| opcgpro-web/public/data/OP16.json（前端展示源） | 同上 | 同上 |

DSL 第二段（Choose OwnCharacter nameEquals 囚犯 + GiveKeyword 阻挡者）已正确，未动。
收尾：`npm run build:cards` 重建 allCards.json（version=18bf1e0a89f3）；`dotnet build` 0 错误 0 警告。
**需重启后端生效**（CardDatabase 启动时一次性加载卡数据）。

## 链路核对
- `OnOppAttackDeclare` 由 `BattleEngine.cs:62` 在对方宣告攻击时 `TriggerEvent` 派发；`CollectListeners` 用 `AttackerIdx` 跳过攻击方、只收防守方（`EffectRuntime.cs:178`）。
- 收集靠 `HasEffectForTrigger` 读 `Info.EffectTags`（`EffectRuntime.cs:226`）——这次补的就是它。
- trigger 级 `oncePerTurn` 已支持，"可以发动" 由 `Choose min:0` 表达可放弃。

## 同类待决（独立大范围问题，本次只报不改）
全库扫描 `abilities` 含「阻挡者」共 356 张，其中约 **56 张** 卡面是「**条件**自赋予阻挡者」（如 OP06-054「手牌≤5则此角色获得阻挡者」、咚!!×N 型、领袖特征型等），却同样在 abilities 硬写了「阻挡者」。
这些卡多有脚本用 `ContinuousEffect.GrantKeyword="阻挡者"`+Predicate 按条件赋予（如 `OP06_054_Borsalino.cs`），但 `HasKeyword` 先查 `Info.Abilities` 就无条件 return true、短路了条件检查 → **变成无条件常驻阻挡者，忽略卡面条件**。
代表卡号：EB02-012/033、EB03-018/044、EB04-056/057/061、OP02-031/074、OP03-090、OP04-005/059/071、OP05-062/086、OP06-010/054/072/113、OP07-024/029/030、OP09-068、OP10-053/099/108、OP11-057/065/096、OP12-012/053/065/066/087/089/100、OP13-031/089/091/106/112、OP14-011、OP15-011/024/053/055/060/068/087、OP16-073/113、P-004/105/113、PRB02-015、ST25-002/005、ST27-004、ST28-002。
处理需逐张核实是否已有「条件赋予」的脚本/持续效果：有则删 abilities 的「阻挡者」；无则需补条件赋予机制（否则删了就永不获得）。建议另起一轮专项处理。
