## #254 OP09-001 杰克斯领袖：对方攻击时无法发动效果

**根因**：DSL 定义在 `Effects/Definitions/_GAP_wf.json` 早已存在，但 `卡牌数据/OP09.json` 的
`effectTags` 是空数组 → `EffectRuntime.HasEffectForTrigger` 收不到该卡，`OnOppAttackDeclare`
触发永不派发（即"DSL加触发段必须补effectTags"的经典坑）。

**修复**：
- `卡牌数据/OP09.json`：OP09-001 补 `effectTags: ["OnOppAttackDeclare"]`
- `_GAP_wf.json`：该触发段补 `"oncePerTurn": true`（原文【每回合1次】；解释器
  `CheckTriggerOncePerTurn` 已支持）。Choose min:0 提供"可以不发动"
- 顺带全量审计 `_GAP_wf.json` 22 张带 triggers 的卡：**P-010 盖德** 同样缺 tag，
  已补 `effectTags: ["OnMyTurnEnd"]`（我方回合结束追加1活跃咚）。其余 20 张齐全
- 重跑 `npm run build:cards`（version=ba84b24a8c29）

## #255 OP15-053 莉贝卡：贴咚后未获得阻挡者效果

**根因**：服务端链路本来是通的（脚本 OnEnterField 注册 ContinuousEffect，
`ActionValidator.HasKeyword` → `GameState.HasContinuousKeyword` 判定、阻挡宣言校验都认）。
问题在快照：`StateSnapshotBuilder` 的 `gainedKeywords` 只序列化瞬时 `CardInstance.GainedKeywords`，
不含 ContinuousEffect 授予的关键词；而客户端 `BattleDefenseOverlay` 按
快照 gainedKeywords + 静态卡面过滤可选阻挡者 → 贴咚授予的【阻挡者】前端不可见、不可选。

**修复**：`StateSnapshotBuilder` 新增 `ContinuousGrantedKeywords`（候选集：
阻挡者/速攻/双重攻击/不可阻挡/流放/可攻击活跃，逐个查 `HasContinuousKeyword`），
并入 fieldCards 的 `gainedKeywords`（Distinct 去重）。前端零改动。

**波及面**：一次修好全部条件授予关键词卡的前端显示/可选（约56张条件阻挡者 +
EB04-057、OP03-004 等贴咚速攻/双重攻击类），也覆盖 #253"阻挡者无UI显示"类反馈。

## #256 OP10-058：满场时二次登场自动挤走最左角色，应让玩家自选

**根因**：`AtomicOps.PlayFromHandFree` 等效果登场原语在角色区满5张时直接
`Characters[0]` 静默送废弃区，玩家无选择权（正常付费出牌路径 GameEngine 早有
OverflowTrash 弹窗，效果登场路径没有）。dedup 中 #243 为同根因。

**修复**：
- `EffectRuntime` 新增 ambient `CurrentPrompts`（AsyncLocal，与 `_ambient` 同设同还原）
- `AtomicOps` 新增 `SqueezeCharacterSlot(s, playerIdx)`：有效果 Prompt 上下文时用
  与正常出牌一致的 `OverflowTrash` ChooseCards(1,1) 让登场方自选 1 张送废弃区
  （非 KO、不触发【K.O.时】）；无上下文/异常时回退旧行为（挤最左），不会卡死
- 统一替换 4 处引擎原语：`PlayFromHandFree` / `PlayFromTrashFree` / `PlayFromDeckFree` /
  `PlayFromLifeFree`
- 统一替换 8 张手搓同款逻辑的脚本卡：EB02-025 / OP01-116 / OP06-003 / OP07-048 /
  OP08-007 / OP08-071 / OP08-073 / OP12-058
- 未动：`CardPlayer.cs`（正常路径已被 GameEngine 拦截，保留为防御性回退）、
  `GameEngine.cs:228`（GM 工具）
