# 2026-06-16 单人测试模式：领袖名称判断一律通过

## 需求
单人测试模式（`VsBot`）下，OP16-015 这类「判断我方领袖名称」的条件应永远成立，便于在任意领袖下测卡。

## 背景
测试模式建房时 `GameRoomManager` 已用 `leaderKeywordWildcard: vsBot` 给双方领袖套 `CardInfo.WithWildcardKeywords()` 克隆，使 `HasKeyword(...)` 一律 true（特征通配）。
但名称判断走 `me.Leader.Info.Name.Contains(...)` / `== / !=`，**不在通配范围内**，故测试模式下领袖名称门槛仍卡住。

## 改动
1. `Cards/CardInfo.cs`
   - 新增 `NameWildcard` 标志（仅领袖测试克隆设置，不污染共享缓存实例）。
   - 新增 `NameContains(string)` / `NameIs(string)`：`NameWildcard` 为 true 时一律返回 true，否则退回真实 `Name.Contains` / `==`。
   - `WithWildcardKeywords()` 克隆中同时置 `NameWildcard = true`（领袖测试克隆同时通配特征+名称）。
2. 把所有「判断**我方领袖**名称」的启用门槛从 `Leader.Info.Name.Contains/== /!=` 换成 `NameContains` / `NameIs`：
   - 通用：`Effects/HandStaticCost.cs`（OP16-015）、`Effects/Dsl/DslInterpreter.cs`（`leaderNameEquals`）
   - 脚本：OP05-040、OP07-013、OP07-101、OP09-109、OP11-100、OP11-107、OP11-115、OP11-117、OP12-080、OP13-016、OP13-021、OP13-051、OP13-052、OP13-075、OP13-082、OP13-098(两处)、OP15-042、OP15-054

## 设计要点 / 例外
- 通配只挂在**领袖**的测试克隆上；角色卡仍用真实名称，故「检索某名称角色」等过滤不受影响。
- **OP10-008 Scotch 未改**：其领袖名称判断是「场上是否已存在『洛克』」的**存在性判断**，若通配会永远认为已存在 → 反而禁用效果，与"让效果可用"的意图相反，故保留真实名称判断。
- 角色名过滤（如检索/收集"路飞""艾斯"等角色）一律保持 `.Name.Contains/==`，不改。
