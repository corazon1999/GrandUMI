卡号: OP16-008
日期: 2026-06-15
现象: OP16-008 斯库亚德登场时，直接弹出"选对方角色"，且能选任意对方角色（含力量>8000的非法目标）KO，完全跳过了"将我方1张原本力量10000的角色放置废弃区"的成本。
根因: OP16.json 中 OP16-008 是早期"近似实现"——triggers 节只有 then(Choose OpponentCharacter → KO)，既无 cost 节，Choose 也无 filter（_doc 自承"忽略力量≤8000的过滤条件及放置10000角色到废弃区的费用"）。DSL 的 PayActivationCost 当时也没有"选我方场上某角色放废弃区"这一成本原语，只有 selfToTrash(放置自身)。
修复:
  1. DslInterpreter.cs PayActivationCost 新增 cost 原语 trashOwnCharacter（仿 revealHand）：按 filter 取 me.Characters 候选，无候选→return false(付不起不发动)；ChooseCards(min 0,max 1) 允许放弃→空选 return false；选中后用 BattleEngine.KOCard 放置废弃区（沿用 selfToTrash 同款通道，不触发被弃角色【KO时】）。候选随 choiceCards 下发牌面。
  2. OP16.json OP16-008 triggers 加 cost.trashOwnCharacter{originalPowerGte/Lte:10000}；Choose 加 filter{originalPowerLte:8000}。
  现执行顺序：登场→先选我方原本10000角色送废弃(无则不发动)→再选对方力量≤8000角色KO。
波及卡牌: 排查 OP16.json 及各 OPxx.json 中"将我方角色放置废弃区作为成本"的 KO/效果类——OP16-008 是当前唯一用 trashOwnCharacter 语义且此前漏实现的。其它"放置自身废弃"走 selfToTrash 正常。新原语 trashOwnCharacter 后续同类卡可直接复用。
预防:
  - 见到 DSL 卡 _doc 含"近似实现/忽略…费用/忽略…过滤条件"字样，即为待补的半成品，应优先补全成本与目标过滤。
  - "可以…成本：…效果"类，成本写进 trigger 的 cost 节(PayActivationCost 付不起/放弃则 continue 跳过 then)，不要把成本塞进 then。
  - 已知近似：DSL 目标 filter 仅支持 originalPowerLte/Gte(卡面原始力量)，"力量不高于N"(当前力量含buff)暂以原本力量近似；若日后要精确，需新增 currentPowerLte 原语(在 Choose case 内借 state 计算 CurrentPower)。
