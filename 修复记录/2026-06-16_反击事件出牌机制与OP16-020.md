---
卡号: 通用机制（反击事件出牌）+ OP16-020
日期: 2026-06-16
现象: 反击阶段（BattleCounter）选中 OP16-020（事件，带 EventCounter）点击"出牌"没有任何反应。
---

## 根因（三层都缺，属未完成的 M3 功能）

"从手牌主动打出反击事件"这条链路从未做完：

1. **客户端 `HandArea.tsx`**：反击步骤点手牌只处理 `c.counter > 0`（反击值卡），其余直接 return；`GameRequest.playCounterEvent` 虽定义但**全项目从未被调用** → 点反击事件无反应。
2. **服务端 `GameEngine.cs` `HandlePlayCounter`**：事件分支（非 useCounterIcon）是 stub `SendError("反击事件 M3 实现")`，直接拒绝。
3. **效果定义 `Effects/Definitions/OP16.json`**：OP16-020 只有 `main`（且 main 还是占位"抽1"，见下），**没有 `counter` 块**。

注：反击事件的**结算引擎本来就好的**——`DslInterpreter` 支持 `counter` 块、`EffectTrigger.EventCounter`，大量脚本/DSL 卡（如 OP16-040、OP16-058）都在用 `AddPowerThisBattle` 等。缺的纯粹是"打出"这一步。

## 修复（实现通用机制，所有 EventCounter 卡从此可在反击阶段打出）

- **服务端 `GameEngine.cs`**：`HandlePlayCounter` 事件分支改为校验（带 EventCounter 标签 + `ActiveDonCount ≥ HandPlayCost`）后 `Track(PlayCounterEventAsync)`。新增 `PlayCounterEventAsync`：复用 `CardPlayer.Play`（按 `HandPlayCost` 扣活跃咚→休息、事件入废弃区）→ `EffectRuntime.Resolve(..., EffectTrigger.EventCounter, ...)` → 仍停在 BattleCounter，重广播 `AwaitCounter`（可连打或 PassCounter）。
- **客户端 `HandArea.tsx`**：反击步骤新增判定 `isCounterEventPlayable`（`effectTags` 含 `EventCounter` 且有效费用 `handCardCosts[i] ?? cost ≤ costActive`），点击发 `GameRequest.playCounterEvent(i)`；金色高亮环扩展覆盖此类卡。
- **`net/GameRequest.ts`、`types/net.ts`**：去掉 playCounterEvent 的"M3"字样注释。
- **`Effects/Definitions/OP16.json` OP16-020 加 `counter` 块**（原文：『可以丢弃我方的1张手牌：本次战斗中，我方最多1张领袖或角色力量+3000。』）：
  ```json
  "counter": { "cost": { "handDiscard": 1 },
    "then": [ { "op":"Choose","prompt":"OwnLeaderOrCharacter","max":1,"as":"$tgt" },
              { "op":"AddPowerThisBattle","target":"$tgt","delta":3000 } ] }
  ```
  仿 OP16-058（同为 OwnLeaderOrCharacter +N），仅多一个 `handDiscard:1` 成本、delta 3000。先扣费移出手牌、再结算，故弃的是"另一张"手牌；手牌不足则 PayActivationCost 返回 false、不发动（语义正确）。

## 取舍 / 已知遗留
- **不触发 `OnOppEventPlayed`**（"对方发动事件时"旁观效果）：避免在对手攻击/非主回合误触发那些假设主回合的监听器。需要时再单独接。
- 机器人仍只会 Pass 反击、不会打反击事件（不在本次范围）。
- **OP16-020 的 main 仍为占位"抽1"，未修**：原文实为『可以将我方1张咚!!转为休息，并公开我方手牌中1张力量8000的角色：抽1』。这是"休息1咚 + 公开8000角色"**双成本**，而 `PayActivationCost` 按固定顺序逐项处理、无回滚——若先 `restActiveDon` 成功再 `revealHand` 被放弃（"可以"=可放弃），咚会被错误休息（部分支付 bug）。需脚本化该卡或扩展 DSL 支持原子多成本后再修。已在 OP16.json 的 `_doc` 标注。

## 波及
- 全库带 `EventCounter` 标签的事件卡现都可手动打出。若某些只有 EventMain 实现、`counter` 块缺失的卡，点击后会扣费但无效果——后续应抽查补 `counter` 定义（本次仅补 OP16-020）。

验证: 服务端 `dotnet build -t:Compile` 零警告零错误；客户端 `tsc --noEmit` 通过。
