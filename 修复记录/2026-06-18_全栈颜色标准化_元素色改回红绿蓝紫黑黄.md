# 全栈颜色标准化：元素色（炎/水/暗/风/地/光）→ 标准色（红/绿/蓝/紫/黑/黄）

> 日期：2026-06-18
> 触发：用户要求"取消所有的炎/水/暗/风/地/光引用和映射"，选定"现在就全栈标准化"。

## 背景

本项目历史上数据层用**元素色**存储颜色（炎/水/暗/风/地/光），显示/效果文本层用 OPCG **标准色**（红/绿/蓝/紫/黑/黄），靠前后端两张映射表桥接。这套双层设计是 bug 温床（脚本写标准色"绿"、数据存"风"→ 判断恒 false，如 OP10-032）。本次彻底废弃元素色，数据层直接用标准色，删除所有映射。

## 正确映射（已用数据验证，非拍脑袋）

| 元素色 | 标准色 |
|---|---|
| 炎 | 红 |
| 风 | 绿 |
| 水 | 蓝 |
| 暗 | **紫** |
| 地 | **黑** |
| 光 | 黄 |

### ⚠ 关键坑：前后端映射方向原本就矛盾，紫/黑 是反的
- 前端 `colorMap.ts` + `globals.css`：暗=紫、地=黑（**正确**）
- 后端 `DslInterpreter.cs` 的 `ColorAlias`：紫→地、黑→暗（**错误**，把紫黑写反）

裁决方法（三重证据，全部指向 暗=紫 / 地=黑）：
1. 阵营统计：元素色"暗"池 431 张里大妈/夏洛特/凯多（紫阵营）命中 33；"地"池 418 张里克洛克达尔/黑胡子（黑阵营）命中 22。
2. 单色起始卡组对照 OPCG 官方：**ST04 凯多/百兽=紫、ST06 赤犬/海军=黑**，ST01 红 ST02 绿 ST03 蓝 ST07 黄 全部吻合。
3. 前端两份配置自洽（暗=紫）。

## 附带修复的真 bug
1. **OP10-032 达斯琪**：原脚本 `Contains("绿")` 配数据"风"恒 false（审查报告 2.2 确定 bug）→ 数据标准化后脚本"绿"↔数据"绿"命中，**自愈**。
2. **后端 DslInterpreter ColorAlias 紫/黑映射写反** → 删除映射修复，此前所有 DSL `color:"紫"`/`color:"黑"` 过滤错色的卡一并修正。

## 给后人的话
- 颜色现在全库统一标准色，**别再引入元素色**（炎/水/暗/风/地/光）。写卡效颜色判断直接用 红/绿/蓝/紫/黑/黄。
- 改卡数据后记得 `npm run build:cards` 重生成 allCards.json，否则 deck-editor 单包不更新（内容哈希永久缓存）。
